# Education Quizzes

Адаптивные учебные самопроверки и страница дня на React, TypeScript и Cloud Firestore. Статический интерфейс публикуется на GitHub Pages. В репозитории находятся только код, общие контракты и обезличенные примеры.

## Спецификации

Начинайте с [карты спецификаций](docs/product/README.md) и [карты всех файлов](docs/product/file-map.md): у каждого файла указаны ближайший контракт, назначение и потребитель. `npm run check:spec` проверяет полноту и ссылки; точечные JSDoc `@see` ведут к отдельным правилам. У целевой архитектуры и действующих маршрутов разные состояния реализации — смотрите их в контрактах.

## Доступ и данные

- Ученик получает отдельные ссылки на страницу дня, тест и список назначений. У родителя свои ссылки на день, список и предпросмотр. Токены ссылок нельзя коммитить или публиковать в логах.
- Код сайта не получает токены МЭШ и Яндекс.Диска. Локальные настройки, снимки дневника, планы, фото, PDF, привязки конкретных страниц и секреты находятся в игнорируемой `.local/` или в закрытой библиотеке вне этого репозитория.
- Новые оригиналы фото браузер отправляет напрямую на Яндекс.Диск по одноразовому адресу доверенного процесса. В Firestore остаются только заявка, связи, статусы, хэши и ссылки. Старые записи с `dataUrl` обрабатываются отдельной миграционной командой `storage sync`.
- Изображения `public/materials/` исключены из исходного репозитория. Ридер использует опубликованные отдельные страницы на Яндекс.Диске; если встроенный просмотр недоступен, показывает ссылку на оригинал.

## Локальные команды

Из каталога приложения или из корня учебного проекта:

```sh
npm run diary -- doctor
npm run diary -- login
npm run diary -- verify
npm run diary -- sync --date YYYY-MM-DD
npm run day -- refresh YYYY-MM-DD
npm run day -- publish YYYY-MM-DD
npm run day -- pull YYYY-MM-DD
npm run storage -- sync-pages
npm run storage -- sync YYYY-MM-DD
npm run quiz -- board-status
```

`storage sync-pages` читает закрытый `.local/material-pages.json` с точными страницами и публикует только нужные PNG на Диске. Новые фото обслуживает `storage:worker`; `storage sync` нужен только для прежних записей с `dataUrl` и удаляет копию из Firestore после сверки. Для педагогической проверки `submissions pull` скачивает подтверждённый оригинал с Диска в закрытую локальную папку.

## Разработка и выпуск

```sh
npm install
npm run prepare
npm run check
```

Хуки Git проверяют формат коммита, линтер и сборку. `npm run publish:pages -- --dry-run` сообщает, нужен ли выпуск сайта; отправка `main` сама сайт не обновляет. Firestore Rules развёртываются отдельно. Перед публикацией проверяйте, что в ветке сайта нет файлов ученических работ или страниц учебников.
