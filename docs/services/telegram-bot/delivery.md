# Маршрутизация, форматирование и Telegram доставка

**Родитель:** [корневая архитектура](README.md); [порты и события](ports-and-events.md); [ledger/outbox](event-ledger-outbox.md).
**Статус:** семейная доставка работает в постоянном Mac runtime. Принята общая [модель Telegram digest](../../shared/design/telegram.md): одинаковая ViewModel для renderer и UI Kit, обычное компактное HTML `sendMessage` и безопасное исключение review без точного задания. Актуальная реализация и её ограничения описаны в [решении компактного digest](../../decisions/telegram-compact-digest-2026-10-18.md). Durable grouping реализована в этой итерации; team routing отсутствует. Фактический выпуск Mac/site и Telegram receipts фиксируются отдельно от наличия локального кода.

## Разделение ответственности

- Recipient resolver применяет проверенные identity links и тип аудитории.
- Policy решает, какие event types получает родитель и команда.
- Grouping собирает сообщения по получателю в окне 30 секунд тишины с жёстким пределом 60 секунд после первого события.
- Renderer — чистая детерминированная функция, формирующая Telegram-safe parts и допустимые context links.
- grammY adapter выполняет Telegram API вызовы и нормализует Telegram errors.

Адаптер доставки не выбирает детей/семьи, а renderer не читает Firestore и не вызывает сеть.

## Маршрутизация

- Родитель/опекун получает события по всем детям каждой активной семейной связи.
- Командный поток на первом запуске направлен Telegram account `@ibnrubaxa`; target должен быть конфигурационным и заменяемым на группу/служебный аккаунт.
- Прямые детские адресаты в MVP не создаются.
- Перед enqueue resolver проверяет active link; перед отправкой повторно проверяет состояние link, чтобы уже отозванная связь не получила отложенное сообщение.
- Приватные поля режутся по роли/`privacyClass`. Team summary и family summary — разные views, даже если event один.

## Группировка и размер

Собирать события по точной chat/family/person/link/child области; закрыть после30секунд тишины, крайний срок готовности группы —60секунд от первого приёма. Фактическая отправка учитывает доступность Telegram и rate limits. Новое событие не продлевает группу за её максимальный возраст. Одна часть содержит максимум6строк фактов и1200символов; последующие факты переходят в нумерованную часть с сохранением порядка и короткой общей шапки. Технические пороги размера/числа событий одной группы открывают следующую, не исключая семьи и не теряя события.

Строка digest по возможности включает точное название задания либо значение, сопровождающий статус и нужную дату/контекст. Общая шапка содержит ребёнка и предмет, когда они едины для всей группы. Поле без подтверждённого значения опускается; его нельзя заменять догадкой. Для `review.changed` требуется точный контекст задания, предмет и подтверждённый статус; событие без них не отправляется и не превращается в пустое статусное сообщение. Поздние события после flush идут в следующую группу.

## Структурный вид

Общий [контракт оформления](../../shared/design/telegram.md) задаёт одну строку ребёнка/предмета и компактные строки по точным названиям задания/значениям со статусом. Большие event heading, divider, footer и повторяющаяся шапка исключены. Одна чистая digest ViewModel используется renderer и UI Kit; Telegram получает обычный `sendMessage` HTML с нативной типографикой клиента, без CSS сайта и обещания произвольных цветов.

`upload.confirmed` означает «Фото получено» и waiting «Ждёт проверки», не правильность работы. `review.changed` получает статус лишь из подтверждённого allowlisted review.status. `quiz.submitted` остаётся ожиданием проверки. `grade.*` выводит значение1–5 с опциональным знаком, не приписывает самостоятельное владение навыком. Поля, которых нет в подтверждённом событии, не выдумываются. Источники/ответы/приватные пути не выводятся.

Safe navigationContext приходит из подтверждённого Firestore day owner и exact task membership. Day token задаёт канонический ресурс, не роль или авторизацию; приложение проверяет участника семьи. Без доказанного контекста кнопки нет. Ссылка ведёт в день; task anchor без поддержки маршрута не придумывается. Демо-кнопка UI Kit разрешена только для явно помеченных демонстрационных сообщений и никогда не открывает семейные данные.

## Telegram formatting и частичные ошибки

Production renderer сохраняет структурные parts версии2: plaintext, безопасный HTML, совместимую JSON модель blocks и проверенную клавиатуру. Новые `format:html` части идут сразу через sendMessage/HTML, receipt format=html. Прежние v2 без format исполняют сохранённый Rich payload и используют HTML fallback только при однозначной неподдержке метода. RichText использует нативные объекты форматирования, HTML tags не вставляются в строки blocks. Каждая часть проходит общий schema validator перед отправкой. Fallback после однозначного отказа unsupported method возможен; timeout/429/5xx не вызывают немедленную повторную отправку другим методом. Пользовательский текст экранируется только при HTML сериализации, а ссылки проверяются по точному host/path/hash без credentials/query/port. Каждая часть дайджеста имеет отдельный outbox receipt. Если часть отправлена, а следующая упала, повторять только незавершённую часть; если API outcome неоднозначен — применять оговорку at-least-once из ledger spec.

Retry/rate-limit детали принадлежат [ledger/outbox](event-ledger-outbox.md). grammY и `@grammyjs/auto-retry` применяются в Telegram adapter; plugin retry не заменяет устойчивую очередь.

## Будущие расширения

Подмодули `templates/<event-type>.md` добавлять, когда event catalog станет независимым. Настройки категорий, locale и альтернативный transport — отдельные контракты, не включать их как скрытые условия в базовый renderer.
