# Цепочка тестов: компактная история и итоговая проверка

**Статус: действующий контракт общего QuizCard, уточнён прямым запросом родителя 16.10.2026.** История по умолчанию закрыта. Родительская иконка запроса нового теста сохраняется при любом результате, включая100%. [Цветовой контракт](result-presentation-proposal.md), [UI Kit](ui-kit.md), [исследование](../research/quiz-history-and-consolidation.md).

## Обнаруженные причины

До изменения композиции `QuizCard.tsx` показывает кнопку запроса только при `points < maxPoints`; 100% исключены намеренно прежним правилом. `earlier.map` выводит историю в причинном порядке исходный → продолжения. `QuizCardAttempt` содержит общий балл, но теряет вычисленные по вопросам исходы `grade`; число верных ответов из балла восстановить нельзя. Исходный тест рассматриваемого примера содержит семь вопросов на одиннадцать баллов, а не одиннадцать вопросов. Исправление одной видимости кнопки не создаст режим широкой проверки: очередь, закрытый план и валидатор также должны различать его и работу по ошибкам.

## Цели и неизменные границы

- Один общий `QuizCard` на странице дня и в списке тестов, общие CSS и ViewModel; предмет меняет источники и содержимое разбора.
- Родитель видит вопросы, верные/частичные/неверные ответы, процент и время в одном месте. Кнопка строки раскрывает разбор без ухода со страницы. Время — только иконка часов, по нажатию четыре прежних поля.
- Исходное задание учителя, страницы и история сохраняются. Завершённые ответы не переписываются; активная попытка и переключатель обязательности следуют действующему контракту без видимой подписи тумблера.
- Существующие ограничения раскрытия ответов действуют и внутри карточки. Родительский доступ не открывает ключи ребёнку автоматически. Перенос ResultCard требует общей безопасной проекции, а не копии UI с другими правами.

## Данные, проценты и сортировка

Единый исход по вопросу: `correct | partial | incorrect | unanswered | pending | excluded`. Частичный ответ не считается полностью верным; отдельный счётчик показывается только при наличии таких ответов. `answered` не заменяет `correctCount`. Непроверенная попытка получает «Ждёт проверки», неизвестные числа не подставляются нулями.

Процент попытки = округлённое `100 × earned / possible`, как сейчас; это процент **баллов**, не доля вопросов. Общий процент цепочки = `100 × sum(earned) / sum(possible)` по полностью проверенным попыткам, включая последнюю. Рядом число включённых тестов; ожидающие проверку перечислены отдельно. Среднее процентов не используется. В примере вся цепочка — 18/32 балла, 56%; отдельно 16 верных из 26 вопросов. Эта историческая статистика не переводит текущие 100% в «не выполнено».

Причинная `quizChain` остаётся исходный → продолжения: от неё зависят последний тест, корень и обязательность. Только копия представления истории сортируется по `submittedAt DESC`; при отсутствующей дате — `createdAt DESC`, затем стабильный `testId`. Поздняя запись ручного разбора в `updatedAt` не переставляет старую попытку наверх. Открытая текущая попытка остаётся сверху; дата «Начат» имеет прежний смысл первой записи ответа. Завершённая история не сортируется по дате просмотра.

## Единое продолжение по всей истории

И автоматическое продолжение ниже85%, и ручной запрос проходят один `continuationPlan` в `assessment/quiz-lineage.mjs`. Триггер решает, нужна ли очередь; содержание зависит от проверенной причинной цепочки до исходного теста. Переход ниже100% больше не является условием показа иконки. До полной проверки или при уже существующем продолжении иконка видна, но недоступна с пояснением. Ребёнок её не видит. Ожидание запроса отделено от сохранённого балла.

При текущих ошибках применяется прежняя формула адресного размера из [графа](assessment-decision-graph.md#followup-threshold). Каждая ошибка получает отдельный новый вопрос; усиление выбирается по всей истории, затем добавляются отдельная прежняя тема, перенос и закрепление. Полный провал не сокращает тест.

При полном результате и запросе родителя стратегия — `consolidation`: `B=max(N0,K)`, `R=min(3,H)`, `N=B+R+1+1`. `N0` — **вопросы** исходного теста, не его баллы; `K` — число целей подтверждённой матрицы всей темы, `H` — число различных групп подтверждённых ошибок всей цепочки. База покрывает каждый исходный вопрос и все цели матрицы; усиление не заменяет базу. Например, исходные7 вопросов на11баллов и хотя бы3 исторические группы ошибок при K≤7 дают12 новых вопросов, даже если последний короткий тест5/5.

Ранжирование групп: число ошибок убывает, давность последней ошибки по причинной цепочке возрастает, затем устойчивый ID. Группа — точная метка `topic`; отсутствующая метка не объединяет несвязанные вопросы. Это воспроизводимое свидетельство, не автоматическое утверждение одинакового смысла разных формулировок. Автор сверяет навыки и учебник предметно. Дополнительное повторение не выдаётся за требование МЭШ.

Команда `npm run quiz -- history TOKEN .local/history.json [PLAN.json]` возвращает `next`: policyVersion, sourceTestId, historyFingerprint, strategy, targetCount и slots. Дополнительный PLAN задаёт `continuation.topicCoverage` для более широкой темы. Закрытый план содержит `continuation` с этими реквизитами, матрицей `topicCoverage:[{objectiveId,sourceId}]` и `checks:[{slotId,questionId,sourceTestId?,sourceQuestionId?}]`. Цели и источники существуют в обычном плане, семейный материал подтверждён; каждый слот связан с отдельным вопросом, каждый пункт матрицы покрыт. Для текущих ошибок сохраняется `followupCoverage`; после100% — его пустой errors при правильном sourceTestId.

Перед create/revise-open CLI заново проверяет всю цепочку, владельца, ручные ответы, fingerprint, объём, покрытие и обычный смысловой план. Несовпадение блокирует запись с причиной. Опубликованные ответы не переписываются. Пустая история, непроверенный ответ, неизвестный источник или неполная матрица не превращаются в выдуманные ошибки.

Детерминированы размер, порядок и источники слотов при одинаковых входах. Формулировки составляет и проверяет оператор, фиксируя пакет; воспроизводимый банк готовых формулировок пока не реализован. Не обещаем одинаковый текст от повторной генерации модели.

## Связь с кодом и проверками

`QuizCard.tsx` — единая закрытая по умолчанию история и родительский запрос; ViewModel сохраняет причинную цепочку и отдельно сортирует представление. `store.ts` и прежние Firestore rules уже разрешают узкий одноразовый запрос после100%: расширять права не требуется. `sync-queue.mjs` ставит prepare-targeted-followup также при нуле ошибок и ручном запросе. Полная история не читается в каждом сканировании; source.historyRequired=true и targetCount=null честно требуют расчёт через history. `scripts/quiz.mjs` проверяет её перед публикацией, переиспользуя уже прочитанную последнюю попытку.

Регрессии: `QuizCard.test.tsx`, `QuizCard.history.test.tsx`, `homeworkStatus.test.ts`, `assessment/quiz-lineage.test.mjs`, `assessment/followup-contract.test.mjs`. Проверяются100%, одноразовый запрос, отказ записи, ожидание и необязательность, закрытая история обеих ролей, сохранение сортировки/источников/баллов, полный провал, старые ошибки, исходный объём, матрица темы, устаревший fingerprint и пропущенный слот. Новых SDK-вызовов и подписок это изменение не добавляет.
