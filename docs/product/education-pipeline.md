# Сквозной протокол обновления Education

Статус: **действующий ручной цикл с машинными барьерами; автономного наблюдателя и автоматического педагогического разбора нет**. Эта спецификация связывает [порт МЭШ](../architecture/school-diary-port-adapter.md), [план](plan-generation.md), [материалы](materials.md), [разбор](review-criteria-provenance.md), [хранение](storage-privacy.md), [dashboard](dashboard.md), [уведомления](../architecture/activity-and-inbox.md) и [навык оператора](../../../skills/education-sync/SKILL.md). Исполнитель не может считать этап завершённым по одному успешному вызову API: каждый этап имеет наблюдаемое условие завершения.

| Этап | Вход и проверка | Выход и потребитель | При сбое |
|---|---|---|---|
| 1. МЭШ | Подтверждённая связь родитель → ребёнок; для каждого урока загружена подробная карточка; профиль и коллекции имеют ожидаемую форму | Полный `snapshot-D.json` с `fetchedAt`, стабильными ID и diff; `day/build`, dashboard | Неполная попытка в `attempts/`; прежний полный снимок не заменяется. `INCOMPLETE_DETAIL` не доказывает отсутствие ДЗ |
| 2. Изменения | Сравнение только полных снимков по ID и содержанию, без ложной дельты от порядка/времени запроса | Добавление, изменение или снятие для ручной смысловой сверки | Несопоставимый раздел не считается отменой; дата последней удачной загрузки остаётся видна |
| 3. Источник | Точная строка МЭШ, оригинал учителя и назначенное издание/страницы; файл проверен по хэшу и лежит на Яндекс.Диске | Закрытый источник-пакет и ссылки в Firebase; `day-source` и проверка работы | Неизвестное помечается `needs-review`; не создаётся обязательное действие по догадке |
| 4. План | ID и `meshText` каждого назначения совпадают с текущим полным снимком; у пунктов есть доказуемое происхождение; исходный лист и координаты фрагментов привязаны к одному оригиналу | Ролевые `dayPages`, `planRevision`, отпечаток плана; клиентские подписки | `day publish` останавливается до записи страниц; фото и старые проверки не удаляются |
| 5. Оценки | Последний полный снимок МЭШ и ручной `learner/grade-snapshot.json` согласованы по предмету, количеству и среднему; при полной ленте также по отметкам и весам | Сводка Firestore; отдельное событие о новой или исправленной оценке | Выпуск дня останавливается, чтобы не показывать устаревший средний. Неполная лента МЭШ не заменяет ручную сверку |
| 6. Индекс и роли | Каждый `homeworkDayToken` ведёт к странице той же даты и опубликованному отпечатку плана; выходные `taskIds` принадлежат своему уроку | `dayDashboards` ученика и родителя в одном пакете с новым днём | Старый индекс остаётся; исчезновение прежней выходной карточки требует записи причины в `.local/weekend-slot-removals.json` |
| 7. Работа ученика | Оригинал загружен на Яндекс.Диск; Firebase хранит путь, хэш, владельца, фазу и все охваченные `taskIds`; очередь перечитана без фильтра даты | Один источник фото может подтверждать несколько номеров; `submissions` готовит разбор | `paused` с причиной; файл без подтверждения Диска не становится `reviewed` |
| 8. Разбор | Оригинальное условие, история попыток, найденный ключ/критерий и степень совпадения; первый подтверждённый разрыв и адресный вопрос | Полный `dayReviewPrivate` для родителя, проекция `dayProgress` для ученика, семейное решение отдельно, уведомление адресату | `unresolved`; не угадывать критерий учителя и не выдавать готовый ответ ребёнку |
| 9. Закрытие | `day publish` и `day dashboard` перечитывают обе страницы и полный индекс после записи; отдельно проверить приватность разборов, медиа и inbox; обновить событие и прогресс; запустить проверки документов | Отчёт с подтверждённым/открытым/неизвестным и датой источника | Частичный цикл прямо назвать частичным, перечислить точку возобновления |

`day build` и `day publish` имеют разную ответственность. Первый обновляет локальный редактируемый план из полного снимка; второй повторно сверяет план **с тем же актуальным снимком**, затем публикует. `day dashboard` проверяет связь локального плана с опубликованной страницей для каждой даты, а не только выходных. Страница дня хранит `sourcePlanFingerprint`; при изменении исходника без повторной публикации индекс не выпускается. Исторический лист 08.10 создан до устойчивых ID МЭШ и имеет явную запись `legacy-manual`; новые дни этим исключением не пользуются.

Снятие ранее видимой выходной карточки — отдельное решение оператора. В `.local/weekend-slot-removals.json` требуется `{"removals":[{"lessonDate":"YYYY-MM-DD","taskIds":["mesh-ID"],"reason":"подтверждённая причина"}]}`. Отсутствие исходного файла либо поля `weekendSlot` без такой записи блокирует публикацию индекса. Удаление записи не удаляет фото, разбор и историю задачи.

**Граница автоматизации:** МЭШ пока обходится вручную по горизонту; точную семантику условия, издание, решение спецкурса и критерий проверки утверждает оператор. Публикация страницы использует Firestore batch без транзакционной проверки версии: параллельные операторы не должны публиковать один день одновременно. Атомарной аренды педагогического разбора нет. Разделение старых разборов требует выполненной миграции и положительного `review-privacy-audit`; ключи онлайн-тестов после отправки всё ещё доступны читающему документ ученику. Эти границы требуют отдельной миграции доступа и данных до расширения на другие семьи. [Реестр незакрытых работ](protocol-audit-2026-10-11.md) содержит приоритеты.
