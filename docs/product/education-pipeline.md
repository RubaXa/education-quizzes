# Сквозной протокол обновления Education

Статус: **действующий ручной цикл с машинными барьерами; автономного наблюдателя и автоматического педагогического разбора нет**. Эта спецификация связывает [порт МЭШ](../architecture/school-diary-port-adapter.md), [план](plan-generation.md), [материалы](materials.md), [разбор](review-criteria-provenance.md), [хранение](storage-privacy.md), [dashboard](dashboard.md), [уведомления](../architecture/activity-and-inbox.md) и [навык оператора](../../../skills/education-sync/SKILL.md). Исполнитель не может считать этап завершённым по одному успешному вызову API: каждый этап имеет наблюдаемое условие завершения.

Между получением источника и семейной карточкой действует [граф общих артефактов](../architecture/shared-artifact-pipeline.md#stages): неизменяемый закрытый исходник, извлечение, сопоставление, обогащение, сверка, адресная связь и ролевая проекция. Общий материал и разбор переиспользуются только при доказанном совпадении; личные оценки и попытки остаются в семейном слое. Реализованные и ещё открытые стадии указаны в контракте явно.

## Синхронизация учебников {#textbook-sync}

После приёма PDF и до построения ДЗ выполни `npm run sync:books`. Повторяемый запуск обходит реестр полных PDF, строит и аудирует локальный индекс каждой страницы, сверяет общий каталог Firebase, восстанавливает его при расхождении, проецирует уже опубликованные страницы всем подтверждённо связанным семьям, публикует недостающие изображения и повторяет проверку. `needs-identification` останавливает полный статус готовности: сначала установи издание и зарегистрируй PDF, затем повтори запуск. При совпадении SHA с готовым общим каталогом приёмник проецирует страницы уже при семейном связывании. Запись `linked` сама по себе не доказывает, что страницы готовы.

## Единый вход в очереди {#sync-inbox}

Отдельно от очередей работы проверяй школьные сообщения в последнем полном снимке МЭШ: `diary/application/school-alerts.mjs` выделяет только явные замечания и опоздания из комментариев к оценкам. `day publish` выпускает их в адресный родительский inbox; для безопасного разового возврата пропущенного события служит `npm run notifications -- school-alerts`. Устойчивый ключ исключает дубль при повторном запуске. Пустой отдельный метод уведомлений МЭШ не закрывает эту проверку. Публикация считается завершённой лишь после успешной записи и чтения родительского документа; при квоте Firestore этап открыт. [Контракт школьных событий](../architecture/activity-and-inbox.md#school-alerts).

В начале и в конце **полного ручного запуска** оператор выполняет `cd education-quizzes && npm run sync:inbox`. Команда только читает Firestore и выдаёт один снимок по всем семьям и детям: загрузки PDF `bookUploads`, файлы работ `dayUploads`, обращения `dayHelp` и отправленные тесты с **открытым письменным ответом**, для которого ещё нет ручного разбора. Тесты, полностью оцениваемые по ключу, не составляют операторскую очередь. Пустая очередь достоверна только при `complete: true`; ошибка доступа или чтения завершает команду с ненулевым кодом и не превращается в ноль. `checkedAt` — время снимка, не доказательство непрерывного наблюдения.

Тот же снимок включает `textbook-pages` для уже привязанной семейной книги без подтверждённой публикации всех страниц. Он сравнивает фактическое число семейных `bookPages` с `pdfPageCount` и хэшем завершённой публикации. Это очередь `publish` с действием `sync-books`; готовая загрузка PDF не скрывает этот незакрытый этап.

`transfer` означает, что передача ещё не подтверждена; `identify` — PDF на Диске, но издание и семейная связь требуют сверки; `review` — работа или тест ждёт педагогического разбора; `triage` — обращение ребёнка зарегистрировано, но `dayHelp` пока не имеет отдельного признака ответа; `investigate` — ошибка либо неизвестный статус. Сами статусы не утверждают, что процесс **сейчас работает**. Для PDF `requested/awaiting-upload` байты находятся в IndexedDB браузера родителя до успешной передачи; один запуск на Mac не может забрать их с выключенного телефона. Запущенный `storage:worker` выдаёт временный адрес Диска и проверяет переданный файл; новая книга после `needs-identification` требует операторского определения издания, индексации и `family:library link`/`link-edition`. Совпавший SHA связывается автоматически.

Каждый открытый пункт получает явное продолжение в журнале запуска: обработан и повторно прочитан; ждёт устройство/внешний доступ; требует идентификации/проверки; либо зафиксирована ошибка и следующий шаг. Старые обращения `dayHelp` не исчезают из сводки автоматически: до появления подтверждённого статуса ответа оператор сверяет их вручную. Полный запуск охватывает **все** семьи и всех детей; адресные ветки не превращаются в пользовательский выбор одного ребёнка. Само отсутствие загрузки PDF не означает, что предмету не нужен учебник: покрытие расписания проверяется отдельно по `books` и `bookRequirements` каждого ребёнка.

После индексации и семейной привязки PDF выполни `npm run storage -- sync-family-pages` по [контракту полного ридера](family-library.md#full-book-reader). Команда публикует каждую PDF-страницу только привязанных изданий и записывает семейные проекции; `pagesPublishedAt` появляется лишь после полного покрытия. Временные ошибки Диска проходят [ограниченный сетевой повтор](storage-privacy.md#network-resilience); при окончательном сбое повтори команду: локальный реестр и уже опубликованные ссылки предотвращают повторную загрузку. В конце сверь для каждой связанной книги `pdfPageCount` с числом опубликованных семейных страниц. Одна индексация не доказывает, что книгу можно открыть в кабинете.

`day build` и `day publish` имеют разную ответственность. Первый обновляет локальный редактируемый план из полного снимка; второй повторно сверяет план **с тем же актуальным снимком**, затем публикует. `day dashboard` проверяет связь локального плана с опубликованной страницей для каждой даты, а не только выходных. Страница дня хранит `sourcePlanFingerprint`; при изменении исходника без повторной публикации индекс не выпускается. Исторический лист 08.10 создан до устойчивых ID МЭШ и имеет явную запись `legacy-manual`; новые дни этим исключением не пользуются.

### Подготовка к контрольной без письменной сдачи {#control-preparation}

Адаптер русского языка классифицирует запись «подготовиться к контрольной» как чтение/самопроверку лишь после установления темы по МЭШ, тетради или явному уточнению семьи. Сырой текст МЭШ и источник уточнения сохраняются раздельно: уточнение родителя не выдаётся за слова учителя. Оператор применяет [навык полного цикла](../../../skills/education-sync/SKILL.md) и [навык тестов](../../../skills/online-quiz/SKILL.md): минимум 20 разнотипных вопросов, проверенный семейный учебник, смесь текущей темы, прежних ошибок, отдельного интервального повторения и переноса. Для русского нужны выбор, ввод буквы или слова и разбор текста/плана; открытый ответ требует ручной проверки. `quiz create` записывает вопросы без ключа в семейное назначение, ключ — в `answerKeys`; `day-source.testPlacements` и `task.testToken` связывают его с устойчивым ID МЭШ, а `requiredPoints` задаёт явный порог. `day publish` сверяет связь и выпускает данные в Firebase, затем `quiz audit-access`, ролевой readback и снимок очереди подтверждают результат. Школьная контрольная и её точные вопросы остаются неизвестными, пока учитель их не предоставил.

Те же развилки и проверка закрытого плана распространяются на остальные предметы через [граф самопроверок](assessment-decision-graph.md#decision-graph). Результат теста обогащает личную траекторию после смысловой проверки, но не общий каталог материалов.

Снятие ранее видимой выходной карточки — отдельное решение оператора. В `.local/weekend-slot-removals.json` требуется `{"removals":[{"lessonDate":"YYYY-MM-DD","taskIds":["mesh-ID"],"reason":"подтверждённая причина"}]}`. Отсутствие исходного файла либо поля `weekendSlot` без такой записи блокирует публикацию индекса. Удаление записи не удаляет фото, разбор и историю задачи.

**Граница автоматизации:** МЭШ пока обходится вручную по горизонту; точную семантику условия, издание, решение спецкурса и критерий проверки утверждает оператор. Публикация страницы использует Firestore batch без транзакционной проверки версии: параллельные операторы не должны публиковать один день одновременно. Атомарной аренды педагогического разбора нет. Разделение старых разборов требует выполненной миграции и положительного `review-privacy-audit`; ключи онлайн-тестов после отправки всё ещё доступны читающему документ ученику. Эти границы требуют отдельной миграции доступа и данных до расширения на другие семьи. [Реестр незакрытых работ](protocol-audit-2026-10-11.md) содержит приоритеты.
