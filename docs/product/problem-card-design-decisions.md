# Решения о дизайне карточки задачи

Статус: действующий контракт для нумерованного листа. Связанные правила: [адаптивная карточка](adaptive-problem-card.md), [граф формирования](card-generation-policy.md), [матрица статусов](status-presentation.md) и [дизайн-система](design-system.md). Перед изменением любого из перечисленных компонентов сравни новый вид с этой матрицей на одном и том же примере исходника, роли и состояния; изменение смыслового слоя требует обновления контракта и снимка до выпуска.

| Компонент | Зафиксированное решение | Что не должно теряться при изменении |
|---|---|---|
| `ProblemGroup` | Один лист над свёрнутым списком номеров, варианты при наличии; короткий `N из M` и единый значок состояния. | Номера, вариант и обязательность считаются раздельно; второй лист не смешивается с первым. |
| `ProblemCard` | Свёрнутый номер с названием, коротким статусом и стрелкой; полный статус в доступном имени. | Нет повторяющейся фразы «Не начато»; открытие номера не открывает остальные. |
| `ProblemStatement` + `SourceFragment` | В раскрытом номере сначала точный фрагмент исходного листа с рисунком, затем дословная запись текста. | OCR не выдаётся за структурированный разбор и не заменяет оригинал. Крупный просмотр сохраняет полный лист. |
| `ProblemStatement` — педагогический слой | Сразу после оригинала цветная область «Как читать условие»: отдельные карточки фактов `Дано` и полоса `Найти`. Она видна ребёнку и родителю **даже при наличии полного `math-route`**. | Факты и искомое не превращаются в грубый текст, готовый ответ или дублирующий решающий шаг. Цвет и сетка сохраняются при `compact`, `standard`, `extended` и на узком телефоне. |
| `ProblemStatement` — происхождение | Родителю рядом с заголовком условия показывается один статусный знак. По нажатию открываются степень подтверждения, источник, совпадение, ключ и заметка. Нижней полноширинной полосы нет. | «Поиск не записан» отличается от документированного `not-found`; без данных интерфейс не заявляет, что поиск уже выполнен. У ребёнка закрытые сведения не появляются. |
| `ParentTaskGuide` | Отдельный свёрнутый родительский маршрут из 2–4 этапов, каждый этап исходно свёрнут; ответ только в последнем. | Маршрут не прячет видимое `Дано / Найти`; `routeProfile` меняет глубину решения, а не геометрию исходника. |
| `WorkReview` + `ProblemUploadButton` | Фото, проверка, адресный следующий вопрос и загрузка остаются при конкретном `problem.id`; одно фото может покрывать несколько номеров. | Кнопка загрузки не исчезает после завершения; отсутствие номера на фото не становится доказательством невыполнения. |
| `StatusIcon` | Одинаковые значения попытки/проверки во всех карточках. | Значок не вычисляет учебный результат; основание результата остаётся в данных и тексте раскрытия. |

## Проверка изменения

Сравни родительскую и ученическую роль на одном листе геометрии с `Дано / Найти` и на математическом варианте с полным маршрутом. На 320, 390 и 540 CSS px проверь свёрнутый лист, свёрнутый номер, раскрытый номер, происхождение закрыто/открыто и родительский маршрут закрыт/открыт. Регрессионная проверка должна подтвердить наличие трёх слоёв исходник → текст → факты/искомое и отсутствие нижней полосы происхождения. Для `not-found` текст должен отражать записанный охват поиска; если запись отсутствует, не подменять её утверждением «искали и не нашли».

Открытый пробел данных: `DaySourceResearch` требует `match`, но не отдельный структурированный список мест поиска. До его введения оператор должен записывать конкретный охват в `match`/`note`; интерфейс не может восстановить его сам. Основание выбора педагогической опоры (`support.evidence`) хранится, но отдельного раскрытия на родительской карточке сейчас нет: его формат требует согласованного компактного решения, чтобы не вернуть лишнюю полосу под карточкой.
