# Доступ и состояние Education

Связанные контракты: [модель Firestore](firestore-data-model.md), [страница дня](day-page.md), [тесты](quizzes.md), [хранение и приватность](storage-privacy.md). Карта: [README](README.md).

Этот документ фиксирует действующую переходную ссылочную схему. Новая схема с личной ссылкой каждого человека и разделением по семьям описана в [модели семьи](../architecture/family-data-model.md), [экранах из данных](../architecture/backend-driven-ui.md) и [журнале действий](../architecture/activity-and-inbox.md). До переноса работ прежние токены страниц остаются отдельным переходным доступом.

Смена личной авторизации проходит по [протоколу ротации](../architecture/family-data-model.md#link-rotation): новый вход проверяется до отзыва старой ссылки для каждого человека отдельно. `personId` и учебные документы сохраняются. Прежние прямые URL дня и теста требуют отдельной миграции и не считаются отозванными при замене личной ссылки.

<a id="routes"></a>
## Маршруты и роли

| Маршрут | Представление |
|---|---|
| `#/day/<studentToken>` | План ученика. |
| `#/day-parent/<parentToken>` | План родителя с источниками и статусами. |
| `#/days/<studentDashboardToken>` | Ученический обзор дней из Firestore. |
| `#/days-parent/<parentDashboardToken>` | Родительский обзор дней из Firestore. |
| `#/t/<slug>~<assignmentToken>` | Попытка или результат теста. |
| `#/my/<boardToken>` | Ученический список тестов. |
| `#/review/<boardToken>` | Родительский список результатов. |
| `#/preview/<slug>~<previewToken>` | Предпросмотр без попытки. |
| `#/dashboard/<boardToken>` | Дополнительный маршрут списка. |
| `#/enter/<personalSecret>` | Вход человека по личной ссылке; после входа секрет убирается из адресной строки. |
| `#/connect/<inviteCode>` | Одноразовое приглашение взрослого: команда локального подключения и состояние заявки. |
| `#/` | Личная стартовая страница после входа; связи и переходы приходят из Firestore. |

В переходных маршрутах токен ссылки даёт доступ к соответствующему документу. Личная стартовая страница использует постоянный `personId`; роль и доступных детей определяют членства в Firestore, переключателя роли нет. Токены не попадают в Git, логи и аналитические URL. В прежних родительском и ученическом представлениях один учебный день, но разные документы и ключи.

<a id="state"></a>
## Владение состоянием

| Состояние | Источник | Инвариант |
|---|---|---|
| Опубликованный план | `dayPages/<token>` | Проекция локального авторского плана; в ней нет байтов фото. |
| Ролевой календарь | `dayDashboards/<token>` | Даты и точные записи МЭШ; ведёт к опубликованным `dayPages`, не содержит байтов фото. |
| Ответы и отправка теста | `assignments/<token>` | Не перезаписываются публикацией дня. |
| Ключ и ручная проверка | `answerKeys`, `reviews` | Отдельны от попытки. |
| Ролевые индексы и просмотр | `dashboard/<boardToken>/assignments`, `seen` | Индексы ведут к общим назначениям; просмотр не меняет ответы. |
| Статус и ссылка на фото | `dayUploads/<studentToken>/files` | После переноса байты живут на Диске; временная очередь описана отдельно. |
| Этап и итог проверки фото | `dayProgress/<studentToken>/items/<taskId>` | Агент пишет через Firebase Admin; родитель и ученик получают изменения через `onSnapshot` без нового выпуска сайта. |
| Семейное засчитывание верного ответа | `dayParentDecisions/<studentToken>/events/<eventId>` | Только родитель создаёт неизменяемое событие по текущей версии проверки; ребёнок и родитель читают, `dayProgress` не переписывается. [Контракт](day-page.md#parent-acceptance). |
| Исходный дневник и план | Закрытая `.local/` | Не является частью публичного приложения или Git. |

`mergeDayPage` добавляет новые пункты и сохраняет прежние статусы, фото и попытки в отдельных документах. При повторном выпуске задания его `testPlacements` заменяются по устойчивому `taskId`: старая ссылка на тест не остаётся вторым действием и не запрашивается как несуществующий документ. Автоматическая отмена задания, снятого учителем, ещё не реализована: не выдавать старое назначение за свежеподтверждённое. [Граница синхронизации дневника](../architecture/school-diary-port-adapter.md) описана отдельно.

<a id="integrity-gates"></a>
## Барьер целостности

Форма основных документов и точные связи заданы в [модели Firestore](firestore-data-model.md#v1). Перед записью `day publish` проверяет обе ролевые проекции и существование каждого теста в назначении и ролевом списке; после записи перечитывает граф. `day audit` сверяет опубликованные даты и страницы семейного каталога. Ошибка связи останавливает выпуск или аудит; она не становится новым блоком интерфейса.

<a id="schema-compatibility"></a>
## Совместимость схемы

Старые читаемые v0/v1 документы нормализуются в клиенте без обратной записи; неизвестная будущая версия требует обновления приложения. [Узкая миграция](firestore-data-model.md#migration) работает с резервным снимком и проверкой ревизии, не сбрасывает попытки и прогресс.
