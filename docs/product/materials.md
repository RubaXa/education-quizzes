# Материалы и страницы учебников

Связанные контракты: [страница дня](day-page.md), [хранение](storage-privacy.md), [источник дневника](../architecture/school-diary-port-adapter.md). Карта: [README](README.md).

<a id="source-metadata"></a>
## Точный источник

При подготовке задания точную связь с учебником и сверенную короткую цитату записывают в закрытый `.local/material-pages.json`. `taskPages` может ссылаться на **любой из 12 ученических учебников** в `library/textbooks/registry.json`: отдельная запись книги и заранее составленный список её страниц больше не нужны. Опубликованная связь `taskPageRefs` находится в документе дня Firestore, а URL и метаданные страницы — в общем каталоге Firestore. Локальный файл не входит в Git. Отрицательный OCR-поиск не доказывает отсутствия текста; внешний материал подписывается отдельно и допускается после проверки полного оригинала.

<a id="mandatory-source-link"></a>
## Обязательная связь нового ДЗ с источником

Повторный `day refresh` может получить новое ДЗ из МЭШ в любое время. Генератор сохраняет точный текст назначения; при изменении текста прежняя сверка сбрасывается. `day publish` **останавливается до записи в Firestore**, если задание помечено `textbook-page-needed`, если статус `textbook-page-linked` не имеет точных страниц или если опубликована лишь часть связанных страниц. Агент сверяет задание с полным PDF и индексом, указывает `taskPages` и оформляет понятные действия. Если нужного учебника в библиотеке действительно нет или текста в нём нет, записывается явный статус с причиной; файл учителя связывается как `teacher-attachment`. Отсутствие совпадения OCR само по себе не разрешает такой статус. Ранее опубликованная страница остаётся доступной, пока новая версия не готова.

Если нужного PNG ещё нет на Диске или его хэш отличается от текущего изображения исходного PDF, `day publish` вызывает `storage sync-pages`: страница извлекается из проверенного PDF, загружается на Яндекс.Диск и получает URL в каталоге Firestore. Повторный запуск пропускает уже опубликованный PNG с тем же хэшем. Клиент читает эту связь из Firestore, поэтому новые ссылки не требуют изменения кода сайта.

Изображение, приложенное учителем в МЭШ, скачивается командой `diary files`, затем `storage sync-teacher YYYY-MM-DD` сверяет SHA-256 и размер, переносит файл на Яндекс.Диск и сохраняет связь с ID вложения в закрытом `diary/files/YYYY-MM-DD/yandex-links.json`. При подготовке дня `day build` подставляет этот URL в `materialLinks` с типом `teacher-attachment`; ридер открывает лист внутри Education. Для уже опубликованного дня новая связь заменяет прежнюю ссылку МЭШ через `materialLinkReplacements`. Сам оригинал и токен Диска не входят в PWA; новая ссылка появляется через Firestore без его перевыпуска.
Для PDF учителя команда сохраняет оригинал на Диске приватно и публикует отдельный PNG каждой страницы; в Firestore попадают только ссылки на эти PNG. `day refresh` запускает перенос обнаруженных изображений и PDF перед сборкой дня; `day publish` останавливает выпуск, если ссылка на такой файл всё ещё ведёт на МЭШ.

<a id="firestore-catalog"></a>
## Каталог Firestore

`materialBooks/{bookId}` хранит издание, предмет, роль, SHA-256 оригинала, число страниц и путь к приватному PDF на Диске. `materialBooks/{bookId}/pages/{pdfPage}` хранит печатный и PDF-номер, `sourceRef`, OCR для поиска, состояние публикации и — только у опубликованного PNG — ссылку Яндекс.Диска и хэш изображения. Все 12 ученических учебников и их страницы индексируются командой `npm run storage -- sync-catalog`. Оригиналы переносятся приватно командой `npm run storage -- sync-library`. OCR служит навигацией: перед формулировкой задания агент сверяет изображение PDF. Браузер не получает токен Диска или оригинал PDF; чтение каталога разрешено только устройству с действующей личной ссылкой семьи, перечисление коллекций запрещено.

Страница дня хранит устойчивые `taskPageRefs` вида `bookId#pdfPage`; клиент получает URL из каталога по этим ссылкам. Прежние `materialLinks` сохраняются как резерв для старых ссылок дня или временной потери доступа к семейной сессии. Повторная публикация не удаляет фото, ответы тестов и привязки текущих заданий.

<a id="private-originals"></a>
## Приватные оригиналы

Полные PDF сохраняются в `app:/PETR/Учебники/Оригиналы/` без публичной ссылки. Состояние загрузки и хэши хранятся в закрытом `.local/yandex-pages/library.json` и в Firestore. Для просмотра ученика публикуются только точные PNG страницы, которые требуются заданию.

<a id="page-publication"></a>
## Публикация отдельной страницы

`storage/material-pages.mjs` получает исходный PDF из закрытой библиотеки, сверяет страницу с индексом и готовит PNG в игнорируемой `.local/`. `scripts/storage.mjs sync-pages` загружает выбранные страницы на Яндекс.Диск, проверяет содержимое, обновляет каталог Firestore и сохраняет индивидуальные URL в закрытом локальном реестре. Команда повторно использует уже опубликованные изображения с тем же хэшем. В исходный Git и ветку сайта PNG, PDF и миниатюры не входят. Firestore получает ссылку и метаданные источника, но не байты страницы.

<a id="material-reader"></a>
## Ридер

`MaterialReader` группирует страницы, показывает миниатюры и встроенный просмотр с номером, стрелками, свайпом и увеличением. `src/lib/yandexPublic.ts` получает публичный предпросмотр по отдельной ссылке Диска без OAuth-токена. Запрос изображения не передаёт `Referer` сайта: загрузчик Диска отклоняет такой запрос кодом 403. Для миниатюры неудачный запрос адреса или самого изображения повторяется до трёх попыток с короткой паузой и обновлением адреса. Пока картинка недоступна, вместо сломанного изображения виден номер страницы; после восстановления сети или возврата в приложение попытки возобновляются. Если встроенный просмотр не может показать страницу, пользователь видит ссылку на оригинал. Ссылка с доступом по владению может быть переслана; [граница доступа](storage-privacy.md#privacy-boundary) остаётся отдельным правилом.
