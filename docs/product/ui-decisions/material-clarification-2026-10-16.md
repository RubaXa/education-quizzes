# Уточнение неизвестного учебного материала

## Основание
Родитель прямо потребовал 16.10: вопрос ребёнку в карточке, фото его записей через существующую загрузку, обработка следующей синхронизацией и сопоставление с семейной книгой. Отсутствующая тема не заменяется догадкой по прежнему тесту.

## Было → стало
Для чтения без названной темы не было пути ответа ученика. Теперь materialRequest показывает адресный вопрос в прежней поверхности инструкций; PhotoUploadControl и PhotoStrip переиспользуются. SourceAnalysis — отдельная типизированная квитанция без оценки ДЗ. Состояние материала учитывается во всех сводках.

## Действия и роли
Ребёнок прикладывает снимки. Родитель видит тот же вопрос и наблюдения без загрузки от лица ученика. Оператор использует submissions validate/review, визуально читает полный материал, затем подтверждает тему или задаёт один уточняющий вопрос. Фотография не означает выполнения повторения. Новых коллекций, подписок и Firebase-вызовов нет.

## Проверки
Ролевой интеграционный тест, состояние неизвестно/передача/получено/тема, запрет verified для источника, совпадение обеих проекций и uploadId, сброс запроса при изменении МЭШ; живой пример UI Kit. Полный npm run check перед выпуском.

## Согласование
Прямая просьба родителя о данном сценарии; существующая поверхность загрузки сохранена. Перед выпуском показывается рабочий интерактивный пример UI Kit с условными данными.
