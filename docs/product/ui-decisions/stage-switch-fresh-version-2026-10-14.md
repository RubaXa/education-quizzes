# Свежая версия разбора перед выбором родителя

## Основание

14.10 родитель показал включённый переключатель этапа «Сверить шесть ответов с требованием» и отказ «Нет доступа. Проверьте личную ссылку». Серверные данные содержат назначение, родительский маршрут ревизии 2 и проверку с теми же двумя ID этапов; события решения ещё нет. Ревизия маршрута была изменена после проверки фото. Действующее правило Firestore для события совпадает с локальным и разрешает этот набор полей в симуляции. Причина конкретного отказа на телефоне не доказана; прежняя общая подсказка о ссылке для всех отказов вводит в заблуждение.

## Было → стало

Клиент отправлял ревизию маршрута и время проверки из открытого состояния страницы. Если телефон держал предыдущую ревизию, сервер отклонял запись. Теперь перед событием клиент читает обе версии с сервера: неизменный набор этапов допускает новую ревизию текста, новая проверка фото или изменённые этапы останавливают старый выбор. Отказ записи после успешных чтений называется отказом сохранения, а не проблемой личной ссылки. Переключатель возвращается к последнему подтверждённому состоянию.

Два адресных чтения происходят только при нажатии. Их частота и причина внесены в [реестр чтений](../../architecture/firestore-read-paths.md); фактический счёт с учётом Security Rules ещё требует живого замера.

## Действия и роли

Только родитель может выбрать обязательность проверяемого этапа. Отдельное событие не меняет исходное фото, критерий, балл или требование МЭШ. Ребёнок видит лишь итоговый семейный выбор. Открытый доступ к родительскому разбору остаётся условием серверного чтения; при его отсутствии виден прежний запрос открыть личную ссылку.

## Проверки

`src/lib/parentCompletion.test.ts` проверяет обновление одной лишь ревизии маршрута и остановку при новой проверке или другой структуре. `npm run check` включает карту спецификаций, UI-контракт, тесты и сборку. Реальное нажатие с телефона не было подтверждено: автоматическая проверка разрешений отклонила контролируемую пробную запись в действующую семейную коллекцию, несмотря на план немедленной очистки. Для подтверждения остаётся проверить обычное нажатие родителя и появление события.

## Согласование

Прямой запрос родителя — исправить неработающий переключатель, сохранив согласованное семейное решение. Правка клиента не расширяет права Firestore. Публикация новых правил и производственная проба с временной родительской сессией требуют отдельного разрешения, если после клиентской правки сервер всё ещё отказывает.

Затронутые файлы: `src/lib/parentCompletion.ts`, `src/components/ParentTaskGuide.tsx`.
