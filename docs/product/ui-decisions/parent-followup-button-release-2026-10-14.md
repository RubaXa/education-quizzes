# Родительская кнопка связанного теста после ошибок

## Основание

Родитель 14.10.2026 показал проверенный английский тест 34/39 (87%) без кнопки рядом с «Результат» и прямо потребовал действие после любого результата ниже 100%. В прежнем выпуске кнопку скрыли флагом до разрешения отдельного правила Firestore. [Публичное описание Duolingo](https://blog.duolingo.com/guide-to-duolingo-practice-hub/) подтверждает полезность короткого повтора прошлых ошибок; нашу формулу объёма задаёт [граф Education](../assessment-decision-graph.md#followup-threshold), а не Duolingo.

## Было → стало

`src/components/QuizCard.tsx` содержал родительское действие, но сборка без `VITE_PARENT_FOLLOWUP_ENABLED=true` его скрывала. Теперь иконка стоит перед «Результат» у последней полностью проверенной попытки с ошибками независимо от предмета и порога зачёта. При 100%, незавершённой проверке и уже существующем продолжении действия нет. У ожидающего запроса иконка неактивна. Исходный балл, исходные ответы и прежние попытки не меняются.

## Действия и роли

Родитель нажимает «Создать связанный тест по ошибкам». `src/lib/store.ts` записывает одноразовый запрос; `firestore.rules` допускает только два поля запроса от действующего родителя этой семьи. Очередной периодический сканер `scripts/sync-queue.mjs` находит запрос и создаёт операторскую работу. Оператор сверяет ошибки и источники, составляет сокращённый тест по [формуле](../assessment-decision-graph.md#followup-threshold), публикует его с `linkedToTestId` и проверяет связь. Ученик видит только сам тест после публикации. Кнопка является запросом на подготовку, поэтому карточка показывает «ждём новый тест» до фактического выпуска.

## Проверки

`src/components/QuizCard.test.tsx` проверяет родительскую кнопку для 87% и 95%, отсутствие у ребёнка, при 100%, до проверки и у старой попытки. `src/lib/quizCompletion.test.ts` фиксирует порог и объём 39/5 → 10; `scripts/firestore-rules-followup.test.mjs` ограничивает запись; общий `npm run check` проверяет связи спецификаций и сборку. Перед выпуском интерфейса отдельно публикуются и сверяются живые правила Firestore.

## Согласование

Прямое требование родителя 14.10.2026: кнопка должна быть при результате ниже 100%, учитывать ошибки, прежние ошибки, сокращать объём и работать для всех предметов. Ранее отклонённое автоматической проверкой изменение прав не обходится: правила выпускаются отдельным проверяемым действием до интерфейса.
