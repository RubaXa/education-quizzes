# Уведомления Education в Telegram

## Назначение

Прямой запрос18.10 и уточнение18.10: внедрить через Luna оформление, связанное с общей дизайн-системой; добавить шаблоны UI Kit и после просмотра реальных примеров сделать Telegram-сообщение компактным. Новый дизайн не меняет учебные факты или правила авторизации. Основание компактного digest — [решение 2026-10-18](../../decisions/telegram-compact-digest-2026-10-18.md).

<a id="компактная-сводка"></a>
## Визуальная система

Решение родителя07.11: «По работе в блоке», включая смешанный итог в одной сводке. Обычный HTML `sendMessage`: общая жирная шапка, предмет и срок один раз, отдельный нативный `blockquote` на работу с жирным названием. CSS в Telegram не передаётся; цвет полоски и размеры определяет клиент. UI Kit использует ту же ViewModel и семантические токены сайта.

Результат всегда выражается словами: ✅ «Зачтено»; ❌ «Ответ неверный»; ✏️ «Ответ верный · ход неполный»; при неизвестном ответе — «Часть зачтена · нужно дополнить», «Нужно исправить» или «Недостаточно данных для проверки» по подтверждённому статусу. Верный ответ сам по себе не означает зачёт. Короткие learner-facing `studentFeedback.confirmed/focus` объясняют подтверждённую часть и точное место. Закрытые решения/критерии из `dayReviewPrivate` не читаются и не включаются. При отсутствии причины она не выдумывается. «Проверено», цветной кружок и технический переход статуса не заменяют результат.

Получение фото сообщает число файлов у точной работы для проверки; старт проверки по одному receipt не утверждается. Не выдавать получение за проверку, не придумывать проценты, очередь или срок окончания. Дедупликация eventId не увеличивает число фото. Зачтённому не назначается новая сдача. Оценки, назначения, расписание и тесты сохраняют свой смысл.

События одного chat/family/person/link/child собираются60секунд от первого события. Прежние receipt цепочки не дробят сводку и не добавляют повторяющиеся reply-цитаты. История, порядок, изоляция и retry receipts сохраняются. Пределы50событий/256KiB на группу,6записей/1200символов на часть сохраняются; превышение размера даёт следующую нумерованную часть. События за пределами минуты — новая сводка. Новые сообщения самодостаточны, без общей кнопки «Открыть день»; сохранённые старые outbox части исполняются неизменно.

## Совместимость и безопасность

Durable outbox сохраняет неизменяемые части сообщения и их формат. Существующие v1/v2 части продолжают проходить общие receipt/retry/restart/membership/channel проверки; текущий compact digest сериализуется в HTML `sendMessage`. Неподтверждённые ссылки, raw source URL, disk path, токены, ответы и приватный payload не отображаются. Канонический маршрут приложения выбирает контекст, авторизация приложения отдельно проверяет родителя; preview не даёт доступа к чужой семье.

## Приёмка

Тесты общего словаря, digest, всех event templates, экранирования/инъекций, русских дат, длины/Unicode, неподдерживаемой схемы, v1 compatibility, частичных receipts и retry; UI Kit без семейных чтений и сетевой отправки. Браузерный скрипт проверяет 320/390/540px, три блока смешанного результата и шапку (до450px на320/390/540), обычный размер шрифта, перенос длинных имён/названий и отсутствие сообщения при контекстном пробеле. Реальные примеры идут только в уже подтверждённый пользовательский чат с явной demo подписью и результатом Telegram API. UI Kit и runtime выпускаются отдельно; локальное изменение CSS не означает публикацию. Первая итерация и её реальные проверки описаны в [решении дизайн-системы](../../decisions/telegram-design-system-2026-10-18.md); компактный формат и текущий статус — в [решении digest](../../decisions/telegram-compact-digest-2026-10-18.md).

Основание возможностей: [Rich Messages](https://core.telegram.org/bots/features#rich-messages), [Bot API](https://core.telegram.org/bots/api#sendrichmessage), проверено18.10.2026. Наличие метода в документации отдельно от фактической доступности API/отображения клиента.
