# Единая система представления учебного действия

## Модель информации {#model}

Согласованный каркас: **известное и источник → вопрос → связь → действие или довод → результат и проверка**. Это общая модель информации, а не обязательная математическая формула. Способ рассуждения выбирается предметом и конкретным назначением. Полное условие остаётся отдельным оригиналом; «Дано» не является второй копией условия. Выделяется значение, а не весь абзац жирным. Каждый подпункт сохраняет собственные данные и искомое.

Родитель видит назначение, источник, метод, последовательность существенных переходов и критерий проверки. Ребёнок видит назначение, известные данные и только безопасную текущую опору. Полный закрытый путь не становится ученическим при сворачивании. Зачёт, получение файла, просмотр шага и физическая сдача — разные факты.

При недостаточном источнике показывается другой вид той же модели: **что уже есть → чего не хватает → почему имеющееся не подходит → где проверено → одно действие**. Неизвестное содержание нельзя заменить выдуманным разбором, произвольным параграфом или повторным запросом доступных страниц.

## Предметные способы рассуждения {#subjects}

| Действие | Известное | Связь и переходы | Результат и проверка |
|---|---|---|---|
| Математическая задача | Величины, единицы, ограничения, рисунок | Модель, уравнение, схема, перебор; объяснение каждого существенного перехода | Искомое, единицы, полнота и подстановка |
| Русский язык | Точный текст, действие и языковой признак | Правило → применение к месту → собственная запись | Выполнено каждое назначенное действие; содержание и грамотность отдельно |
| Английский | Упражнение, контекст, коммуникативная задача | Языковой признак или план собственного текста; аудио отдельно от чтения | Все содержательные требования и допустимая языковая форма |
| История | Автор, время, контекст, подтверждённые факты | Вопрос → тезис → свидетельство → причинная связь или граница вывода | Обоснованное объяснение; не произвольный единственный ответ |
| Литература | Назначенные главы и эпизод | Трактовка → фрагмент → объяснение связи | Допускаются разные доказанные трактовки; чтение и декламация различаются |
| Биология | Структура, наблюдение, признаки | Строение → функция → объяснение; сравнение по признакам | Связь подтверждена материалом, а не только назван термин |
| География | Карта, текст, данные, условные знаки | Явление → причина → последствие; легенда → наблюдение → вывод | Объяснение или локализация; отдельное ЦДЗ не заменяется тестом |
| Информатика | Данные, состояние, код, границы | Условие → переход состояния → следующий проход | Вывод, завершение, крайние случаи |
| Технология | Назначенная схема и материалы | Ограничения → порядок действий → собственное изделие | Свидетельство изготовления; знание правил не доказывает практический навык |
| Организационное действие | Что взять или передать и срок | Подготовить → взять → сдать, без фиктивного решения | Подтверждение именно физического действия |

## Граф, контракт и настоящий макет {#graph}

`presentationContracts` — реестр канонических композиций и обязательных информационных полей. Продукт правила получает один утверждённый контракт через `presentationContractForRule`; незарегистрированный продукт отклоняется. Один renderer применяется в дне, спецкурсе и UI Kit. Новая задача меняет проверенные данные, а не создаёт отдельный JSX.

Каждый узел и ребро `decision-registry` имеют `presentationContractIds` и `uiScenarioIds`. Ссылка «Макет» открывает выбранный сценарий с `focus`, показывает контракт, компоненты, проверки и обе роли. Для составной задачи есть отдельный пример с несколькими подпунктами. Технические owner/CAS/publication/knowledge шаги честно обозначают своё видимое следствие: отдельного семейного экрана у них нет.

Каталог обязан вызывать реальную композицию потребителя: математические `math.problem` и `special.sheet` используют `ProblemTaskCard` вместе с `ProblemStatement.support`, а не похожую оболочку без данных. Состояние недостающего источника использует настоящий `MaterialRequest`. Закрытая карточка не считается проверкой её содержимого.

## Барьеры и границы доказательства {#gates}

Нативный publisher и адресная коррекция используют одни проверки. До записи отклоняются полное условие в fact, шаблонное искомое, общая плитка вместо нескольких подпунктов, универсальная очередь шагов вместо конкретного метода, дублированные rows/blocks, длинный первый уровень и повторный запрос имеющихся страниц. Это структурные и ограниченные текстовые проверки: они не доказывают правильность числа, достаточность свидетельства или отсутствие педагогического спойлера. Отдельное чтение оригинала и проверка смысла обязательны.

Регрессия должна пройти цепь «источник → данные → реальный компонент → обе роли и раскрытия → native gate». Проверяется составная задача, недостаточный источник, полученное фото без повторного запроса, история зачёта и production CSS на мобильной ширине. Макет без `support`, тест только ID и зелёный exit без readback не закрывают эту цепь.

Коррекция оформления не создаёт попытку, не меняет условие, ключ, критерии, зачёт, `checkedAt` или срок. Штатный адресный CLI сохраняет историю, проверяет владельца и CAS и перечитывает обе роли. Новое расписание для этого процесса не требуется.

## Исследовательское основание {#evidence}

Это дизайн-вывод из исследований, а не научный закон о единственном представлении любого задания. [IES, 2007](https://ies.ed.gov/ncee/wwc/Docs/PracticeGuide/20072004.pdf) поддерживает разобранные примеры, сопряжённые слова и изображения и объяснение переходов; такая рекомендация не оправдывает декоративную схему или стену готового ответа. [McNeill et al., 2006](https://public.websites.umich.edu/~krajcik/Papers/McNeill_et_al_JLS_2006.pdf) исследовали структуру научного объяснения и постепенное уменьшение опор в химии; эффект не объявляется автоматически доказанным для каждого предмета.

[EEF: предметная грамотность](https://educationendowmentfoundation.org.uk/education-evidence/guidance-reports/literacy-ks3-ks4) различает предметные способы читать и обосновывать. [IES: понимание и интерпретация текста, 2008](https://ies.ed.gov/ncee/WWC/PracticeGuide/8/Published) поддерживает объяснение с опорой на текст и разные обоснованные интерпретации. Поэтому общими остаются поля и компоненты, а не числовая формула или единственный ответ.
