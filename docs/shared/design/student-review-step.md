# Наглядный текущий шаг ученика

## Текущий шаг

Прямое требование родителя01.11: понятная модель и действие по текущей попытке во
всех ученических разборах, без готового ответа и служебного текста. Общие слова о
начале работы не заменяют точного места. У завершённой/принятой работы нет нового
вопроса. Нехватка фото не превращается в математическую ошибку.

## Модель и действие

ReviewActivity получает только опубликованную опору текущего вопроса. Общие
действия: выделить фрагменты, собрать последовательность из данных карточек,
разложить карточки по группам, вписать свою запись в незавершённую модель. Необязательная схема связывает карточки с линиями
фигуры, клетками исходного поля или цепочкой известных связей. Это один компонент для математики, языка,
литературы и истории; предмет определяет авторские данные, а не ветвь рендерера.

Нажатие сразу меняет наглядную запись. Отклик отражает только выбор ученика,
без скрытой проверки, вычисления неизвестного, показа следующей ветки или оценки.
Можно отменить/сбросить выбор; состояние локально, не отправляется, не сохраняется
как учебная попытка и не меняет зачёт. Это опора прежнего вопроса, не новый тест.
Исходный вопрос остаётся видимым; одна и та же формулировка не дублируется вокруг модели.
Все кнопки44px, клавиатура/фокус/aria-pressed, SVG с доступным названием,320px и темы.

## Граница доступа

activity входит в allowlist presentation версии1. Нет полей correct/answer/expected,
оценки, закрытого критерия, HTML или произвольного кода. Корректная схема всё равно
требует отдельной смысловой проверки на спойлер: весь публичный документ и раскрытия
читаются вместе. Полный родительский путь не копируется в activity автоматически.
Служебные ограничения и неизвестность помощи остаются закрытой историей проверки.
Технический конвейер и обязательность практики не являются объяснением для ребёнка.

## Миграция и проверка

Реальные текущие вопросы редактируются адресно по снимку/ожидаемому digest. Сохраняются
ID, статус, checkedAt, история попыток, файлы, семейные решения, источники и закрытый
путь; прежнее представление архивируется. Текстовые старые документы не объявляются
визуальными только из-за наличия общего компонента. Охват миграции подтверждается
инвентаризацией и обратным чтением. Будущие проверки обязаны выбирать осмысленную
опору текущего шага; универсальная декоративная карточка не удовлетворяет контракту.

UI Kit использует реальный WorkReview и публичный projector. Отдельные примеры:
модель с выбором линий, сборка выражения, языковой фрагмент, группировка и завершение.
Проверяются точные роли, клавиатура, локальный сброс и сохранность результатов;
отдельно — опубликованная ученическая проекция семьи и живой ученический экран.

Новая публикация submissions для partial/needs-fix требует activity; новый/исправляемый
question guidance тоже проходит этот барьер. Photo-help CLI принимает структурированный
JSON с text/presentation.activity. Старые результаты читаются совместимо и не получают
синтетических новых заданий. Редактор scripts/student-review.mjs работает в dry-run
без --apply, применяет пакет одной транзакцией по двум digest и архивирует прежний
вид в закрытых studentViewEdits. Прежние документы архивируются, сохраняются статус, критерий и
семейный статус; только публичные формулировки плана синхронизируются с новой подачей.

В ученическом первом уровне нет повторной служебной строки «Ответ не установлен /
Ход не показан»: состояние и зачтённая часть уже выражены плашкой и подтверждением.
Взрослый сохраняет эти диагностические метаданные.

После проверки общий стартовый LearnerFlow доступен в закрытом раскрытии
«Вернуться к условию и плану». Его начальный вопрос не стоит открытым перед
адресным разбором текущей попытки. При новой checkedAt раскрытие сбрасывается.
До первой проверки стартовый план остаётся доступен как раньше.
