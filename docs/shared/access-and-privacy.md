# Доступ и приватность: общие границы

## Общий ресурс, права из авторизации

Прямое решение пользователя18.10.2026 распространяется на **все возможности сервиса**, а не только календарь: один адрес определяет ресурс (день,тест,попытку,результат,историю,задание,материал), подтверждённое членство человека у конкретного ребёнка определяет разрешённые данные и действия. Видимый маршрут,кнопка,название предмета или знание URL не назначают роль. Различие ролей не создаёт отдельной сущности или дубликата результата.

Каждый источник/адаптер должен проверять владельца и права до выдачи данных. Роль определяет состав документов/полей,историю,пояснения,ключи,доступные команды и объём чтений. Закрытые данные нельзя сначала передать всем клиентам и затем скрыть интерфейсом. В Firestore выбор разрешённой проекции и Security Rules работают вместе; правила не являются фильтром полей ответа. Кэш,подписки и серверные операции сохраняют тот же scope семейного членства; отзыв доступа закрывает экран и не оставляет чужую проекцию. Права на материалы дополнительно требуют семейного основания.

Общие компоненты сохраняют одинаковый смысл действия; родительские и ученические действия доступны по проверенным полномочиям. Личная ссылка входа идентифицирует человека и остаётся персональной; после входа учебный URL общий. Прежние role-prefixed адреса допускаются только как совместимые aliases и не повышают права.

**Граница реализации:** общий адрес календаря/дня и выбор его проекции уже работают через LearningRoute. В `src/App.tsx` маршруты тестов/истории ещё содержат прежнее различие `t`/`preview` и `my`/`review`; перенос этих ресурсов на общий resolver остаётся открытой миграцией,а не выполненной функцией. Для каждого такого переноса нужны сценарии одной ссылки под обеими ролями,точного ребёнка,чужой семьи,отзыва доступа и отсутствия закрытых полей в ученическом ответе. Детальный контракт — [доступ и состояние](../modules/families/access-and-state.md#authenticated-learning-routes).

Этот контракт связывает существующие правила; детальные права принадлежат [семейной модели](../modules/families/README.md), [Firestore](data/firestore.md), [хранению](../modules/materials/storage-privacy.md) и `firestore.rules`.

| Граница | Обязательное правило |
|---|---|
| Семья/ребёнок | Проверенные `familyId`, `childId`, роль и source account; имя и текст источника не подтверждают право |
| Ссылки | Личные токены не коммитятся и не попадают в публичные логи; родительский и ученический доступ различаются |
| Закрытый разбор | Ключи, ответы и педагогические пояснения не копируются в открытые документы или командные уведомления |
| Медиа | Общий оригинал не даёт семье автоматического права; семейное основание и проекция проверяются отдельно |
| Серверный процесс | Admin/server Firestore SDK использует IAM и обходит клиентские Security Rules; credentials остаются закрытыми |
| Публичный Git | Код и обезличенные контракты; личные работы, learner-профиль, секреты и `.local` остаются вне него |

Код: `firestore.rules`, `src/lib/personalAccess.ts`, `scripts/lib/admin-firebase.mjs`, `day/material-access.mjs`. Клиентские роли и доступ реализованы частично в соответствии с переходной семейной моделью; будущий Telegram registry и его IAM ещё проектируются. Новый путь доступа требует своей проверки владельца и допустимого раскрытия.
