# Как устроить небольшой живой UI Kit

Дата: 16.10.2026. Задача — интерактивная страница внутри Education, без отдельной платформы документации и массового переписывания интерфейса. [Принятый контракт](../shared/design/ui-kit.md).

| Первичный источник | Что используем |
|---|---|
| [Ant Design — Customize Theme](https://ant.design/docs/react/customize-theme/?locale=en-US) | Различать базовые значения, производные/смысловые токены и специализированные настройки компонента. Параметр компонента не должен случайно менять соседние компоненты. Это принцип структуры; библиотека Ant не добавляется. |
| [Material 3 — Foundations](https://m3.material.io/foundations/) и [Color roles](https://m3.material.io/styles/color/the-color-system) | Называть цвет по роли: поверхность, текст на поверхности, действие, состояние. Токены связывают дизайн с кодом, а состояния и доступность являются частью контракта компонента. |
| [Atlassian — Foundations](https://atlassian.design/foundations) | Основы отделяются от каталога компонентов: цвет, типографика, отступы, сетка, значки, скругления и доступность. В первом разделе описываем используемые основы, не обещаем полную миграцию. |
| [Scottish Government Design System](https://designsystem.gov.scot/) | Компонент — переиспользуемая часть UI; составной паттерн решает пользовательскую задачу. Поэтому индикатор результата и история попыток представлены на разных уровнях. |
| [GOV.UK — Tag](https://design-system.service.gov.uk/components/tag/) | Документация содержит не только примеры, но смысл применения и ограничения; одинаковые состояния имеют согласованный цвет. Информационная метка не маскируется под кнопку. |

## Выбор для Education

Навигация «Основы / Компоненты / Составные сценарии» использует знакомые предметные названия. Жёсткая иерархия атомы/молекулы/организмы не вводится: размер DOM не объясняет владельца доступа и поведения. Простые примитивы лежат в `components/ui`, учебные композиции остаются в `components`, вычисления состояния — в `lib`, токены — в существующем общем CSS.

Для компонента показываем: назначение → работающий пример с изменяемыми входами → правила состояний → когда применять и где не применять → используемые токены → связанные сценарные проверки. Пример импортирует исходный компонент. Данные условные; входы не делают запросов к учебной базе. Не создаём вторую библиотеку компонентов только для каталога.

Стартовый объём: цвета и текущие токены, общие индикаторы, пример истории тестов. Следующие элементы добавляются по мере подтверждения общих потребителей и API. Для будущих форм, раскрытий и изображений сохраняются их отдельные обязанности и права; постепенное извлечение проверяется адресно. Это архитектурный выбор проекта, а не требование перечисленных систем.
