# Метод, модель и наглядный ход решения

## Метод и модель

Родительский путь отвечает на вопросы: что дано, что требуется найти, почему выбран
этот метод, какие связи следуют из условия, какие переходы отделяют от ответа и почему
проверка полна. Название задачи уже находится снаружи; плашка называется «Ход решения»
или «Разбор», без повторения номера, темы и роли родителя.

Метод выбирается по структуре конкретной задачи и уже начатому способу ребёнка.
Перебор требует границ и полноты, таблица сопоставляет случаи, граф объявляет смысл
вершин и рёбер, схема отражает величины и отношения, уравнение следует из объявленных
связей, инвариант объясняет сохранение величины. Допустим обоснованный гибрид. Другой
правильный метод не объявляется ошибкой. Название олимпиады не определяет единственный
обязательный метод. Не добавлять граф или формулу только для украшения.

Основание: замечание родителя и методические примеры сборника Иванюк/Кириллов
«Задачи о турнирах», 2019, с.5–6. Перенос принципа на другую задачу — собственное
предметное решение автора, а не приписанная сборнику рекомендация.

## Представление

Общие блоки поддерживают отдельно короткий текст, типизированную формулу MathML,
уже утверждённую визуальную модель, последовательность переходов и выбор одного
случая из конечного перечня. Формула не хранится смесью абзаца и псевдокода.
У каждого обозначения есть смысл, у каждого нового числа — происхождение.
Родитель видит карту метода и открывает нужный этап; длинная запись ученика раскрывается
отдельно от эталонного перехода. Внутри перебора видны все случаи и подробности выбранного.
Цвет, типографика и оболочка берутся из приложения; прежнее оформление плашки сохраняется.

`guide.method` описывает выбранный подход, основание и короткую последовательность.
`stage.blocks` задаёт структурированное содержание существующего этапа. Старые rows/expected
поддерживаются; наличие общего рендерера не означает содержательную миграцию всех старых
решений. При обновлении проверяются существующие длинные пути, а не только условный образец.

## Доступ и история

Полный путь хранится в закрытом guide. Ученик видит текущую опору и один вопрос,
соотнесённые с его попыткой; полные случаи и ответ автоматически не публикуются.
Ручное раскрытие всего этапа переносит только блоки этого этапа по общему allowlist,
без соседних этапов, закрытых source.ref/excerpt, критериев и будущих веток.
Явная публичная HTTPS-ссылка на математический источник внутри выбранного этапа допустима. Проверка спойлеров
для текущей подсказки включает все её раскрытия.

Редактура родительского пути увеличивает ревизию guide, сохраняет sourceRevision задания,
ID/порядок этапов, источники, прежние решения семьи, попытки, файлы и checkedAt проверки.
Это отдельная адресная операция с проверкой ожидаемой ревизии и обратным чтением.

## Проверка

Проверяются подлинность источника, метод и полнота собственного вывода; источник метода
не подменяет решение конкретной задачи. Отдельно проверяются публичный срез, выбранный
этап, недопустимые вложенные поля, сохранение ID и истории, короткая плашка без дублей.
Браузерный проход использует собранное приложение и реальные ролевые данные, проверяет
формулы, переключение случаев и отсутствие переполнения на мобильной ширине.

## Адресная редактура

`npm run guide:edit -- .local/edit.json` проверяет пакет без записи; `--apply` применяет
его с compare-and-set и обратным чтением. Пакет: `version:1`, точные `pageId/taskId`,
`expectedGuideRevision`, исходный `sourceRevision`, причина и полный новый `guide`.
Разрешено редактировать представление существующего пути. ID и порядок этапов,
источники и reviewLabels остаются прежними; прошлый guide сохраняется в закрытом
`guideEdits`. Операция не пишет страницы, проверку, попытки, фото и семейные решения.

`SolutionBlocks` — единый renderer для родителя и явно раскрытого этапа ученика.
Формула — дерево number/symbol/operator/text/row/fraction/power; сетка объявляет размеры,
ячейки и оси; граф — вершины с названиями и координатами, связи по ID. Случаи ограничены
конечным списком, показывают одну выбранную ветвь; незаявленные поля отклоняются.
Firestore разрешает blocks только при точном равенстве блокам выбранного stage.
Нельзя записать их в hint, подмешать соседний stage или самостоятельно расширить ключ.

Реализация общая для всех разборов. Содержательная миграция охватывает семь текущих
семейных путей; старые исторические решения сохраняют совместимый формат и не
объявляются автоматически переписанными по методам. Схемы берутся из структуры задачи,
а не из декоративного шаблона. Весь путь первоначально свёрнут до карты и этапов.

Таблица comparison хранится как `rows:[{cells:[...]}]`. Массив массивов несовместим
с Firestore Standard; общий валидатор отклоняет его до записи, renderer читает cells.
Адресный редактор также проверяет вложенность с запасом для архивирования guide.
[Ограничение типов Firestore](https://firebase.google.com/docs/firestore/manage-data/data-types).
