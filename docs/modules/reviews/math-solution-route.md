# Математический маршрут родителя {#math-route}

Статус: действующий контракт для нумерованной математической задачи и спецкурса. Общая оболочка и приватность описаны в [предметном разборе](subject-aware-guidance.md#parent-card). Этот документ задаёт повторяемую подготовку следующего листа; пример № 6 в `.local/day-source-2026-10-14.json` не подставляется в другие задачи.

Для приложенного учителем листа спецкурса дополнительно действуют [правила оригинала и нумерации](special-course-card-overlay.md#teacher-sheet); глубина математического решения выбирается независимо от них.

Если в листе подготовки несколько вариантов, сначала выдели вариант, затем каждый номер внутри него. Один и тот же печатный номер в двух вариантах получает разные устойчивые ID. Родительский математический маршрут готовится по каждому пункту, а переключатель обязательности действует на вариант целиком. Это семейный объём тренировки: запись МЭШ «подготовиться» не становится указанием сдать оба листа. [Общий контракт вариантов](card-generation-policy.md#practice-variants).

## Когда применять {#selection}

Для отдельной задачи, где нужно вывести ответ из условия, готовь `parentGuide.kind = worked-solution`, `presentation = math-route`. [Общий граф карточки](card-generation-policy.md#math-adapter) выбирает `routeProfile` по глубине **конкретной** задачи, а не по предмету: `compact` (`solution → answer`), `standard` (`given → solution → answer`) или `extended` (`given → relations → calculation → answer`). У всех этапов устойчивые ID. Одинаковое правило действует для обычной математики и спецкурса. Для `compact`/`standard` запиши `depthReason` и не убирай из объединённого блока нужные данные и обоснования. Утверждённый маршрут № 6 остаётся `extended`. Набор коротких примеров может получать общий компактный список, но это отдельная композиция поверх того же адаптера.

Новые записи МЭШ по математике и спецкурсу получают `mathRoutePolicyVersion: 1` при сборке. После сверки листа каждый **нумерованный** пункт обязан иметь закрытый маршрут независимо от возраста записи и наличия этого флага; `day publish` и адресный `problem-support` останавливаются при пропуске с перечнем номеров. Для нового листа спецкурса нельзя поставить `reviewed`, оставив приложенный PDF неразобранным на номера. Предварительную точную запись МЭШ в состоянии `needs-review` это не задерживает. Старые опубликованные страницы и фото сохраняются: при адресной миграции добавляются только закрытые разборы, без пересоздания результатов ученика.

## Подготовка каждого нового номера {#pipeline}

1. Сохрани точный текст МЭШ, дату урока и срок сдачи. Визуально сверь учительский PDF и выдели устойчивый `original.attachmentRef`, SHA-256 и `crop` именно этого номера. Сохрани дословное `original.text`; если рисунок важен, не заменяй его пересказом.
2. Собери закрытый источник-пакет: семейный учебник и страницы, если назначены; точный оригинал учителя; найденные официальные/авторские ключи и возможные прототипы с прямыми ссылками. Для спецкурса пройди [поиск вариантов](../../research/special-course-source-provenance.md), сравни слова, числа, рисунок и ответ. Поисковый сниппет — кандидат, а не проверенный ключ. При отсутствии точного ключа выведи ответ независимо и сделай обратную проверку, обозначив степень подтверждения взрослому.
3. Выбери профиль по числу независимых связей и переходов. Для короткой задачи объедини данные, связь и действие в `solution`; для средней выдели `given`, затем `solution`; для полной следуй четырём смысловым этапам ниже. Короткими строками называй число с единицей, его смысл, переводы единиц, обозначения до первой формулы. Первый `hintPreview` направляет к данным без решающей связи. `revealPreview` показывает только этот этап.
4. В полном маршруте запиши **этап 2 «Связи»**: каждое уравнение рядом с словами условия и пояснением знака/операции. В сокращённом маршруте помести те же пояснения в `solution`. Проверь, что все обозначения объявлены и связь доказана исходником. Подсказка спрашивает о нужной связи, раскрытие показывает её прямо.
5. В полном маршруте запиши **этап 3 «Вычисление»** строками `запись + почему переход верен`; в сокращённом это часть `solution`. Остановись до численного ответа. Не скрывай нужную алгебру в фразе «решаем уравнение». Подсказка относится к ближайшему переходу, а не выдаёт результат.
6. Запиши **последний этап «Ответ»**: крупный результат; ниже отдельная свёрнутая `verification` по условию. Готовое число, правильный вариант и полная проверка не появляются в шапке, более ранних этапах, ранних подсказках или ученических данных. `revealPreview` последнего этапа явно называется показом ответа.
7. Для каждого этапа сохрани `source.kind/ref/excerpt/label`, `expected`, `rows`, `hintPreview`, `revealPreview`; номер версии `revision` увеличивай при изменении исходника или существенном изменении разбора. `day publish` и `problem-support` проверяют структуру, точную связь цитаты с условием, а родительский пакет публикуют отдельно в `dayTaskGuides/{studentToken}/items/{taskId}`. До выпуска перечитай оба `dayPages`: полный маршрут и ключ туда не попадают.
8. После фото сопоставляй `review.items[].stageId` с теми же ID. Отдельно оцени ответ и видимость хода. Открывай первое **подтверждённое** расхождение; эквивалентный верный способ не ошибка, отсутствие строки на нечётком фото — неизвестность. Взрослый выбирает один этап и уровень `hint` либо `reveal`, видит предпросмотр, затем адресно передаёт только выбранный текст. Ученик получает событие в личной карточке и колокольчике; история помощи не доказывает самостоятельного освоения.

Нельзя заменять отсутствие подготовленного решения повторением одного шаблонного текста, самостоятельно расширять ДЗ учителя или публиковать весь родительский разбор ребёнку.
