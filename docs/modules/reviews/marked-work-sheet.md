# Лист письменной работы с пометками

## Назначение

По одобренному26.11 макету английского письменный разбор показывает оригинал,
распознанную запись и адресные пометки учителя. Это представление существующей
проверки на ребре `review:support` → `support:component` в `WorkReview`, а не новый
вердикт, тест или попытка. Сохраняются результаты, фотографии, источники, история,
диалог, семейные решения и загрузка следующей работы.

## Данные и приватность

Необязательное `studentFeedback.presentation.sheet` версии1 содержит название и
блоки `{id,uploadId,location,parts}`. Часть содержит дословный `text` и необязательную
пометку `{id,status,comment}`: correct, incorrect, partial, unreadable, corrected.
Текст и статус задаёт проверяющий после чтения фотографии; клиент не распознаёт,
не исправляет и не оценивает запись. `corrected` сохраняет первоначальную запись
и поясняет уже принятое исправление. Пустое/нечитаемое не становится ошибкой.
Полный ключ и ещё не найденный ответ запрещены во всех ученических комментариях.
Родитель получает тот же лист и прежний закрытый путь отдельно. В DayPage
родительский learning-route не скрывает лист: когда отдельный WorkReview не нужен,
показывается тот же WrittenReviewSheet без второго вердикта.

ID пометок и блоков уникальны; размер ограничен. Общий валидатор отклоняет
неизвестные поля, HTML, ссылки и ключи внутри схемы. Публикация проверяет ссылку
на настоящий upload этого задания и владельца, CAS исходных документов и смысловую
проверку автора. Это новые поля существующих документов, без новой подписки.

Старые записи без sheet показывают только сохранённые публичные observations из
studentFeedback.steps с подписью «Распознанные фрагменты». Это не новая полная OCR.
Без них видны оригиналы и честное отсутствие расшифровки, без просьбы переслать фото.
Исторический лист использует только обратную совместимую публичную проекцию своей
попытки. Автоматической переоценки или массового перезаписывания старых работ нет.

## Поведение и iPhone

Переключение «Лист с пометками / Оригиналы» локальное. Каждый оригинал доступен
через общий WorkArtifactImage; полный оригинал — сохранённая ссылка на Диск.
Нажатие на подчёркнутое/обведённое место раскрывает комментарий непосредственно
после его абзаца, сохраняя место на листе. Есть текстовый статус и доступное имя;
цвет не единственный сигнал. Повторное нажатие закрывает комментарий. Клавиатура
использует обычные кнопки; изменение документа сбрасывает выбор.

На320–430px одна колонка; нет боковой панели, hover-зависимости, фиксированной
ширины, горизонтальной прокрутки текста и изменения масштаба страницы.
Touch-цель44px, основной текст16px, длинные слова/формулы переносятся. Вкладка
истории явно отделяет предыдущую проверку от текущего результата.

## Публикация и проверки

Штатный `review:presentation sheet .local/packet.json [--apply]` добавляет только
лист к существующему feedback, включая verified. Он сохраняет checkedAt, статус,
items, критерии, uploadIds, history, tutoringPlan и результаты. Коррекция листа
архивируется отдельно и не создаёт попытку. После транзакции перечитываются обе
проекции и неизменные зависимости. Сначала export, потом dry run и apply.

Регрессии проверяют схему/роли, чужое фото, CAS, неизменность оценки и истории,
многостраничность, клавиатурное раскрытие и production CSS на iPhone-размерах.
UI Kit использует настоящий WorkReview с синтетическим листом. Семейный английский
проверяется адресно под двумя авторизациями; личные данные не входят в Git.
