# Доступ и состояние Education

Связанные контракты: [модель Firestore](../../shared/data/firestore.md), [страница дня](../school-diary/day-page.md), [тесты](../assessments/quizzes.md), [хранение и приватность](../materials/storage-privacy.md). Карта: [README](../../product/README.md).

Этот документ фиксирует действующую переходную ссылочную схему. Новая схема с личной ссылкой каждого человека и разделением по семьям описана в [модели семьи](README.md), [экранах из данных](../synchronization/backend-driven-ui.md) и [журнале действий](../notifications/inbox.md). До переноса работ прежние токены страниц остаются отдельным переходным доступом.

Смена личной авторизации проходит по [протоколу ротации](README.md#link-rotation): новый вход проверяется до отзыва старой ссылки для каждого человека отдельно. `personId` и учебные документы сохраняются. Прежние прямые URL дня и теста требуют отдельной миграции и не считаются отозванными при замене личной ссылки.

<a id="routes"></a>
## Маршруты и роли

| Маршрут | Представление |
|---|---|
| `#/day/<canonicalDayToken>` | Общая ссылка на учебный день; вид определяется авторизованным участником этой семьи/ребёнка. |
| `#/days/<canonicalDashboardToken>` | Общая ссылка на календарь; родитель видит разборы и свои действия, ребёнок — загрузку и разрешённую помощь. |
| `#/day-parent/<legacyToken>`, `#/days-parent/<legacyToken>` | Старые совместимые адреса. Не задают роль, нормализуются к общей ссылке после проверки сессии. |
| `#/t/<slug>~<assignmentToken>` | Попытка или результат теста. |
| `#/my/<boardToken>` | Ученический список тестов. |
| `#/review/<boardToken>` | Родительский список результатов. |
| `#/preview/<slug>~<previewToken>` | Предпросмотр без попытки. |
| `#/dashboard/<boardToken>` | Дополнительный маршрут списка. |
| `#/enter/<personalSecret>` | Вход человека по личной ссылке; после входа секрет убирается из адресной строки. |
| `#/connect/<inviteCode>` | Одноразовое приглашение взрослого: команда локального подключения и состояние заявки. |
| `#/` | Личная стартовая страница после входа; связи и переходы приходят из Firestore. |

В переходных маршрутах токен ссылки даёт доступ к соответствующему документу. Личная стартовая страница использует постоянный `personId`; роль и доступных детей определяют членства в Firestore, переключателя роли нет. Токены не попадают в Git, логи и аналитические URL. В прежних родительском и ученическом представлениях один учебный день, но разные документы и ключи.

<a id="state"></a>
## Владение состоянием

### Адресная диагностика роли {#access-diagnostics}

Причинная [локальная LDD-трасса](browser-access-trace.md) различает загруженную сборку, восстановление личности, серверное членство, выбранный маршрут и переданную карточке роль. Она не пишет в облако и доступна штатным read-only инструментом `diagnostics:browser`; remote probe ниже остаётся отдельным default-off механизмом, её наличие в коде не означает разрешённый или выполненный production rollout.

`npm run family -- inspect-access <personId>` — read-only проверка конкретного зарегистрированного участника: серверное членство, профиль, семейный указатель, shortcuts, обе проекции календаря/текущего дня и источники выходного блока. Она обнаруживает коллизию ролевых aliases, неправильную основную ссылку, чужого владельца и пропавшее задание. Повторное обращение к одному документу в запуске дедуплицируется. Ответ содержит только метаданные/хеши ссылок, число чтений и коды расхождений; секреты, тексты работ и решения не печатаются. Непустой issues означает разрыв данных; пустой issues не доказывает личность/сборку конкретного браузера и не закрывает пользовательский дефект. Команда не переключает роль и не перепубликует планы. Проверка активного link-status отдельно от этого графа недостаточна.

Если контрольный браузер не воспроизводит дефект, используется временная адресная диагностическая запись actual projection. `family diagnostics-start <personId> [minutes]` включает окно30минут (максимум60), `diagnostics-read` читает до20записей этого участника/семьи, `diagnostics-stop` немедленно закрывает окно; запись expiry подтверждается обратным чтением. Роль, права, учебные данные и ссылки не меняются. Окно передаётся через существующий snapshot членства, дополнительных клиентских чтений/подписок нет.

При монтировании общей карточки клиент пишет один last-state документ clientRoleDiagnostics/deviceUID: person/family/child, подтверждённая роль членства, роль профиля, фактически переданный parent-признак, наличие закрытого guide, тип экрана и время/expiry. Текст задач, ответы/фото, токены, полный URL, IP и user-agent не передаются. Одинаковые8карточек дают1запись; приход guide допускает ещё одну. До включения/после expiry, для чужого ребёнка или иного Auth UID записей нет. Ошибка диагностики не меняет учебный сценарий. Rules допускают только own-UID запись своего действующего человека/ребёнка до операторского expiry, с точным whitelist полей; чтение клиенту запрещено. Диагностика не доверенный источник прав и не может сама исправить/выбрать роль. Отсутствие отчёта означает отсутствие измерения, а не исправление; старый исполняемый клиент без probe не появится автоматически в телеметрии.

### Роль учебного экрана из сессии {#authenticated-learning-routes}

Общее правило [ресурса и полномочий](../../shared/access-and-privacy.md) действует на все возможности: тесты,попытки,результаты,историю,материалы и действия. Описанный ниже resolver реализует его для календаря и дней. Сохранившиеся различия тестовых URL — миграционный долг,не разрешение определять роль из адреса.

Адрес выбирает ребёнка/день, но никогда не повышает и не понижает роль человека. LearningRoute сопоставляет точную пару familyId/childId с членством авторизованного профиля, затем выбирает внутренний ролевой документ. Пока вход не подтверждён, карточка не рисуется в ученическом режиме по умолчанию. Отсутствие входа/членства/метаданных даёт явную ошибку доступа, не чужую ролевую проекцию. Отзыв личной ссылки, смена deviceSession или членства закрывает экран.

Для `#/`, общего календаря и известного текущего дня первый кадр берётся из сохранённого профиля того же устройства; нового блокирующего экрана проверки прав нет. Auth/grant/device/member сверяются в фоне с metadata-only подтверждениями. Сетевая ошибка сохраняет прежний локальный вид; подтверждённый отзыв закрывает его, а подтверждённая смена членства снимает прежнюю проекцию до одного обновления профиля. Если обновление опять противоречит членству, показывается ошибка без цикла. Неизвестный исторический день требует одного адресного identity-read. [Прямое решение о local-first](../../decisions/local-first-role-recovery-2026-10-18.md) заменяет прежний серверный барьер; локальное состояние не выдаёт новых удалённых прав.

Смена сохранённого контекста в другой вкладке инвалидирует module memory/старые чтения и обновляет уже открытые PersonalEntry/LearningRoute без нового входа. Промежуточное удаление контекста при замене личности закрывает старый вид, но не восстанавливает старую серверную привязку; после сохранения нового профиля открывается соответствующий вид. Поздний callback прежнего слушателя не удаляет новый кабинет. Хранилища установленного приложения и отдельного браузера независимы; правильный результат контрольного браузера не доказывает состояние пользовательского устройства.

Отзыв/ошибка слушателя принадлежат конкретной сессии (`personId/deviceUid/linkToken`). Перед очисткой callback сверяет её с уже сохранённым контекстом: другая новая сессия не удаляется, даже если StorageEvent ещё не доставлен. Память старого входа инвалидируется, открытые потребители принимают новый сохранённый профиль по прежним local-first/UID правилам. Событие LDD `stale-revocation-ignored` объясняет эту ветку. Настоящий отзыв текущей сессии по-прежнему закрывает вид; ученик не получает родительских полномочий. Это предотвращение подтверждённого порядка событий, не заявление об атомарной транзакции между процессами браузера.

Исходная личная ссылка после успешного входа потреблена: повторная инициализация не исполняет её заново. Смена сохранённого профиля в другом табе также отменяет прежний intent входа, даже если App ещё содержит старый enter-маршрут после очистки URL.

При открытии личной ссылки другого человека тот же анонимный Firebase UID не означает прежнюю личность. С начала redemption прежняя сессия в памяти недоступна. Параллельные restore у inbox/календаря/карточки присоединяются к тому же переходу до чтения профиля; не восстанавливают и не сохраняют прежнего человека. Неудавшийся вход не возвращает прежнюю роль молча. Старый запрос, начатый до смены личности, отсекается sessionRevision. Это отдельная гонка от устаревшей роли членства и покрывается тестом реального personalAccess.

Бюджет личного старта остаётся две подписки grant/device и по одной на видимую семью. Обычный тёплый запуск не перечитывает профильный граф; подтверждённое расхождение является исключением. PersonalEntry пересоздаёт только подписки членства после обновления профиля, LearningRoute сохраняет свои три подписки (для исторического дня при повторном разрешении нужно ещё одно точное чтение identity). Это проверяется интеграциями с настоящим ProblemTaskCard, включая смену роли в обе стороны, запуск с корня, личный вход и отзыв. Сами карточки и подготовленные решения не меняются.

Общий публичный адрес использует канонический student token как идентификатор ресурса; это не роль. shortcuts.dashboardTokens и shortcuts.dayTokens содержат старые ролевые aliases, а dayPages/dayDashboards.viewTokens связывает проекции того же ребёнка. Родительский профиль выбирает закрытые чтения только после проверки членства. Firestore rules по-прежнему запрещают ребёнку читать родительские guides/reviews и родительский индекс. Сами ролевые токены не дают права на эти данные. Существующие подготовленные решения не переносятся в ученическую страницу.

Для календаря alias разрешается из уже загруженного личного профиля без нового чтения индекса. Только неизвестный старому кэшу alias требует одного обновления профиля; неизвестный чужой alias отвергается. Для произвольного исторического дня требуется одно адресное чтение metadata dayPages, затем существующие подписки соответствующей проекции. Непрерывного polling и обхода всех дней нет. Publisher и attach-current-day сохраняют метаданные обеих ролей и aliases; изменение только ссылок не меняет учебных статусов.

Родительский вид: оригинал/точный текст/Дано–Найти, значок происхождения, подготовленный свёрнутый маршрут и проверка работы; кнопок «Нужен ориентир?» и загрузки решения нет. Ученический: общий исходник/состояние, запрос ориентира, только разрешённые этапы, загрузка фото; закрытого маршрута нет. Проверяется одна и та же общая ссылка под обеими сессиями, включая старые role-prefixed aliases, неизвестный вход и отзыв доступа. Тест с вручную переданным parent=true не доказывает корректность маршрутизации. Необновлённый личный профиль может временно использовать свой прежний известный alias, но он тоже никогда не определяет роль; после обновления shortcut адрес нормализуется.

| Состояние | Источник | Инвариант |
|---|---|---|
| Опубликованный план | `dayPages/<token>` | Проекция локального авторского плана; в ней нет байтов фото. |
| Ролевой календарь | `dayDashboards/<token>` | Даты и точные записи МЭШ; ведёт к опубликованным `dayPages`, не содержит байтов фото. |
| Ответы и отправка теста | `assignments/<token>` | Не перезаписываются публикацией дня. |
| Ключ и ручная проверка | `answerKeys`, `reviews` | Отдельны от попытки. |
| Ролевые индексы и просмотр | `dashboard/<boardToken>/assignments`, `seen` | Индексы ведут к общим назначениям; просмотр не меняет ответы. |
| Статус и ссылка на фото | `dayUploads/<studentToken>/files` | После переноса байты живут на Диске; временная очередь описана отдельно. |
| Этап и итог проверки фото | `dayProgress/<studentToken>/items/<taskId>` | Агент пишет через Firebase Admin; родитель и ученик получают изменения через `onSnapshot` без нового выпуска сайта. |
| Семейное засчитывание верного ответа | `dayParentDecisions/<studentToken>/events/<eventId>` | Только родитель создаёт неизменяемое событие по текущей версии проверки; ребёнок и родитель читают, `dayProgress` не переписывается. [Контракт](../school-diary/day-page.md#parent-acceptance). |
| Исходный дневник и план | Закрытая `.local/` | Не является частью публичного приложения или Git. |

`mergeDayPage` добавляет новые пункты и сохраняет прежние статусы, фото и попытки в отдельных документах. При повторном выпуске задания его `testPlacements` заменяются по устойчивому `taskId`: старая ссылка на тест не остаётся вторым действием и не запрашивается как несуществующий документ. Автоматическая отмена задания, снятого учителем, ещё не реализована: не выдавать старое назначение за свежеподтверждённое. [Граница синхронизации дневника](../school-diary/README.md) описана отдельно.

<a id="integrity-gates"></a>
## Барьер целостности

Форма основных документов и точные связи заданы в [модели Firestore](../../shared/data/firestore.md#v1). Перед записью `day publish` проверяет обе ролевые проекции и существование каждого теста в назначении и ролевом списке; после записи перечитывает граф. `day audit` сверяет опубликованные даты и страницы семейного каталога. Ошибка связи останавливает выпуск или аудит; она не становится новым блоком интерфейса.

<a id="schema-compatibility"></a>
## Совместимость схемы

Старые читаемые v0/v1 документы нормализуются в клиенте без обратной записи; неизвестная будущая версия требует обновления приложения. [Узкая миграция](../../shared/data/firestore.md#migration) работает с резервным снимком и проверкой ревизии, не сбрасывает попытки и прогресс.


### Страница UI Kit

`#/ui-kit` — публичный каталог компонентов в общей оболочке, без токена семейного доступа. Только условные примеры; персональные учебные документы не читаются. [Контракт](../../shared/design/ui-kit.md).
