# Общие числовые результаты: цвет, метка и полоса

**Статус: принятый контракт результатов тестов, 16.10.2026; выпуск проверяется отдельно.** Родитель утвердил уплотнённую таблицу и представленную цветовую шкалу. Реализация: `resultPresentation`, общие `ui/result`, `QuizCard`, `QuizResultCard` и `ResultView`; примеры — [UI Kit](../../shared/design/ui-kit.md). [Исследование](../../research/result-colour-and-density.md), [матрица](../../shared/design/statuses.md), [дизайн-система](../../shared/design/README.md). Отдельная предлагаемая шкала школьных отметок ниже ещё не принята; общий адаптер среднего не меняется.

## Смысл цвета

| Значение | Тон | Число и знак |
|---|---|---|
| Полностью проверенный тест: 85–100% баллов | success / зелёный | Процент в светлой зелёной метке, тёмные зелёные баллы и заполнение полосы; `CircleCheck` |
| Полностью проверенный тест: 50–менее 85% | attention / янтарный | Та же композиция, янтарная метка/баллы/полоса; `CircleMinus` |
| Полностью проверенный тест: менее 50% | error / красный | Та же композиция, красная метка/баллы/полоса; `CircleX` |
| Результат ожидает проверки | waiting / синий | «Ждёт проверки», без выдуманного процента и длины результата; `Clock3` |
| Черновик, заполняются ответы | accent / фиолетовый | «Ответов X из N», полоса заполнения; `CircleDot` |
| Результат/максимум неизвестен либо невалиден | neutral / серый | «Нет результата»/«Нужна сверка», без подстановки нуля; `CircleHelp` |

Неначатый тест показывает нейтральные 0 из N и пустой трек. 0% после полной проверки — результат с нулём баллов. Неначатый тест и тест без доступного ключа не становятся красными 0%. Ошибка загрузки или доступа отображается как технический сбой, а не плохой ответ ученика. Школьная оценка, выполнение задания и полученные баллы остаются разными осями.

Процент классифицируется по исходному отношению earned/possible до округления. Значения 84,99 и 85 по разные стороны порога не должны оба показывать одинаковые зелёные 85%. При пересечении границы обычным округлением сохраняем нужную дробную точность (до двух знаков без округления вверх); неполные 99,999% не превращаем в идеальные 100%. Процент и цвет общий для метки, числового балла и полосы данного результата. Частичные баллы и числа полностью верных вопросов различаются.

## Школьные оценки и средние

Нельзя превращать средний 4,60 в 92% и красить по порогу теста 85%. Тон среднего поступает из текущего модуля оценок и модели риска: allFives/excellent — success, watch — attention, остальные и неустановленный риск — neutral. Рабочий ориентир прогноза не является школьным правилом округления. При выборе новой шкалы оценок потребуется отдельное решение, не скрытая замена needsAttention.

Для отдельных школьных отметок предлагается адаптер относительно действующей годовой цели «все 5»: 5 — success; 3 и 4 — attention («до цели 5»); 1 и 2 — error. Это предложение, не автоматическая оценка знания и не утверждение, что школьная 4 неверна. Альтернативная педагогическая шкала требует явного выбора. Число вопросов, знаменатель и вес оценки остаются нейтральными: они не сообщают успеха. Число подтверждённо верных ответов можно выделять success, ненулевое число ошибок — error; у каждой величины остаётся подпись.

## Один компонент и одна политика

Общие роли реализации: `ResultBadge` (число, единица, знак, фон), `ResultMeter` (доля набранных баллов), `ResultMeter` с kind=answers (число заполненных ответов). Они используют действующий `StatusIcon`, семантику информационной метки и `--edu-status-*-bg/ink`; новых палитр внутри QuizCard, таблицы, ResultView и GradeBadge нет. Общий чистый селектор возвращает tone и значение из явного kind: quiz-score, school-mark, grade-average, completion, answer-progress. Предмет/экран не меняет пороги локально.

Ширина полосы = фактическая доля, её цвет = общий tone. Градиент «красный → жёлтый → зелёный» на одной полосе не используется: 78% не выглядит зелёным справа. Для нулевого балла полоса имеет нулевую длину; красная метка остаётся видимой, минимальный заполненный пиксель ради цвета не добавляется. Запрос итогового теста не перекрашивает прежние 100% в жёлтый: баллы остаются success, новое ожидание — отдельный waiting-статус.

Светлые пары берутся из действующих токенов: success `#236b46 / #e8f6ed`, attention `#865715 / #fff2dd`, error `#8b263e / #fff1f2`. Эти тёмные чернила используются и для заполнения. В макете есть тёмные пары для проверки будущей темы; это не означает, что тёмная тема уже внедрена в приложение. Контраст текста минимум 4,5:1, значимой полосы/иконки с соседним фоном — 3:1; основной текст и focus проверяются на реальной поверхности. Цвет дополняется числом, подписью и знаком. Оплаченные чтения Firebase от такой политики не зависят; новые подписки/запросы не нужны.

## Матрица внедрения

| Потребитель | Изменение | Что сохраняется |
|---|---|---|
| QuizCard, QuizProgress, история | Общие процентные метки и полосы; плотная таблица | Корень/цепочка, права, часы, исходное ДЗ, ошибки и обязательность |
| ResultView / ResultCard | Те же тона для баллов и исходов вопросов | Предметное объяснение и ограничения раскрытия ключа |
| GradeBadge / DayDashboard (дальнейшая миграция) | Общие цветовые токены через адаптер среднего | Данные, источники, прогноз и комментарии МЭШ |
| Счётчики уроков, ParentHome, разбор работ (дальнейшая миграция) | Общая палитра состояний | Собственный критерий выполнения; не подмена его процентом теста |
| Общий Progress в формах | Явный вид заполнение/результат | Черновик 100% заполнения не объявляется успешным тестом |

## Обязательные проверки

1. Границы: 0, 49,99, 50, 84,99, 85, 99,99, 100; отсутствующий/нулевой максимум, отрицательный и превышенный балл. Цвет и подпись согласованы до/после форматирования.
2. Один и тот же результат во всех перечисленных потребителях даёт одинаковую пару цветов. Все JSX/CSS ссылаются на этот контракт, чтения не добавлены.
3. Заполнено 5/5 без отправки — accent, отправлено без проверки — waiting без балла, проверено 5/5 — success. Родительский запрос сохраняет зелёный результат и добавляет синее ожидание.
4. Средний 4,60 не прогоняется через тестовый процент. Тон от watch/excellent сохранён; номера, знаменатели и неизвестные данные не окрашиваются как успех.
5. Контраст всех ink/bg и заполнения/трека, светлая палитра и отдельно проектные тёмные пары; скринридер и режим без различения цвета сохраняют смысл по числам и подписям.
6. Таблица: метаданные внутри той же кнопки, площадь касания 44px, отступы 6px, дата отдельно; 320/390/540px, длинные названия, большие баллы, частичный и ожидающий разбор без обрезки.
