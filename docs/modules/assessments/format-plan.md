# Детерминированный состав самопроверки

## Решение

Основание: запрос родителя17.11.2026 — тесты по математике и истории стали
состоять только из ручного ввода. Различие `short/long` не является балансом
выбора и самостоятельного ответа. Прежнее правило «математика — открытая запись
по умолчанию, выбор только по отдельной просьбе» заменено этим контрактом.
Сохранённые попытки и ответы не переписываются.

## Вход и план

`npm run quiz:plan -- INPUT.json OUTPUT.json` работает локально без credentials.
Вход: `version:1`, `subjectAdapter`, упорядоченные уникальные `questionIds`,
`purpose:mixed-practice|vocabulary-dictation`, `history` — JSON штатного
`quiz history` либо `null` вместе с честным `historyGapReason`.
Выход кладётся в закрытый assessment plan как `formatPlan:{input,blueprint}`.

Собственное продуктовое правило версии1, а не научно установленная пропорция:
обычный профиль получает около половины вопросов с выбором; при последнем
проверенном результате ниже85% — около двух третей. При трёх и более вопросах
остаются один короткий самостоятельный ответ и одно объяснение. Для двух —
один выбор и один самостоятельный ответ. Один вопрос допустим только в отдельной
ветке словарного диктанта. Неизвестная история не превращается в низкий результат.
Количество продолжения по-прежнему задаёт существующая полная цепочка попыток.

План содержит неизменяемые слоты по ID, группу взаимодействия и допустимые типы:
`selection` → single/multiple/figure; `production` → short/number;
`explanation` → long. Эти типы используют существующий `QuizQuestionCard`;
новых макетов и полей интерфейса этот инструмент не создаёт.
Диктант требует `short` для всех слов и прежнюю полную проверку источников,
а не произвольное исключение с текстовой причиной.

## Барьеры и пределы

`quiz validate/create/revise-open` пересчитывает план, проверяет его совпадение,
каждый слот и фактический тип вопроса. Отсутствие плана, другая последовательность,
подмена истории или набор из одних полей ввода блокируют публикацию. При живом
создании продолжения входная статистика сверяется с уже читаемой полной цепочкой;
нового пути чтения Firestore нет. Старые export/review и исправления заголовка
не требуют изменения вопросника.

`npm run check:assessment-formats` входит в общий `npm run check`: регрессии
математики9short+2long и истории4short+4long, корректный смешанный вариант,
низкий/неизвестный результат, подмена плана, диктант и соответствие компоненту.
Проверка механически доказывает форму и привязки, но не истинность факта,
достаточность объяснения или понятность текста: это остаётся предметным разбором
по оригиналу. Офлайн вход не доказывает происхождение истории без серверной сверки.
