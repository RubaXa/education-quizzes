# Детерминированный план действий синхронизации

## plan

Штатное начало полного цикла — `npm run education -- begin --apply`: обязательная последовательность `queue.scan → project.plan → project.collect` при каждом вызове. Она не использует недавний запуск вместо свежего сбора. Неполный inbox останавливает запуск; partial сбор остаётся явным частичным результатом для независимой работы. Это начало, не автоматическое педагогическое исполнение и не complete. Старый discover сохраняется для отдельной диагностики, но один discover не считается полным началом EducationSync.

Каждый штатный `queue.scan`, включая `education discover/finalize --apply`, формирует закрытый `stdout.routePlan` из уже прочитанных ученических страниц и активных операторских задач. Дополнительных Firestore/МЭШ-запросов нет. Для каждого `(familyId,childId,date,taskId)` сохраняются предмет, адаптер, известные и неизвестные данные, следующий шаг, последовательность действий и проверка результата. Действующие `quizDecision`, `openMaterialRequest` и предметные контракты остаются источниками правил; новый план не является второй системой оценки.

`npm run education -- plan SCAN_RUN_UUID` извлекает этот план из успешной закрытой квитанции queue.scan, проверяет полноту inbox и пишет private JSON с правами0600. В stdout только путь, время и агрегаты маршрутов. Старые квитанции без routePlan явно требуют нового discovery. Команда читает локальную квитанцию: она не делает старый план свежим, не запускает сбор и не является доказательством завершения цикла. Полные 42 даты, обработка changed/pending, обе роли и конечный inbox обязательны независимо от no-work frozen-пакета. Маршруты не копируются в ученические документы или телеметрию.

## sources

| Наблюдаемое состояние | Следующий шаг | Что нельзя утверждать |
|---|---|---|
| Нет точной страницы/файла, нет валидного запроса | recover-source: семейный поиск → поиск точного доступного интернет-оригинала → адресный materialRequest ребёнку → ожидание фото | Нельзя ограничиться скрытым source-unavailable, придумать тему или требовать полный PDF от родителя |
| Запрос материала уже опубликован | await-source-upload → source-analysis → разрешение запроса по доказательствам → новый план | Нельзя требовать фото повторно или считать источник выполнением ДЗ |
| Источник/объём ещё не сверены | review-instruction, выделить только подтверждённые действия | Нельзя назначать повторно старую выполненную работу по расплывчатой ссылке на прошлый урок |
| Подтверждённое чтение/устное/контрольная | действующий quizDecision/граф самопроверок | Нельзя угадывать неизвестную тему или создавать эквивалентный активный тест |
| Уже связан тест | читать фактическую попытку, ключ и историю | Наличие ссылки не означает завершение/освоение |
| Подтверждённое письменное | точное условие и критерии → закрытый родительский маршрут → безопасная проекция → фото | Нельзя выдавать ребёнку готовую работу или требовать лишнее оформление |
| Прямой platformResult completed | сохранить проверяемое доказательство результата | Нельзя из школьного результата вывести неизвестный ход или самостоятельность |
| Неизвестное действие/тип | review-instruction или unsupported-job/event | Нельзя молча пометить complete |

`material-needed` использует прежний устойчивый ID очереди; обнаружение расширено с отсутствующей книги до отсутствующих точных страниц/файла без валидного materialRequest. Публикация валидного запроса закрывает только шаг запроса источника. `enrich-task` и `classify-assignment` остаются открытыми до собственных доказательств. Фотографии постепенно восстанавливают подтверждённое покрытие семейного источника; частичный набор не объявляется полным учебником, внешний PDF не объявляется семейной загрузкой. Сам поиск и визуальное установление издания остаются работой агента.

Предметные адаптеры: математика — math-solution-route; спецкурс дополнительно требует происхождения полного листа; русский — письменная структура/языковые критерии; литература — текстовые основания; английский — language-in-context; история — анализ источника; география — карта/источник; биология — структура/функция; другие предметы — общий subject-aware-guidance. Это выбор контракта, а не автоматическое решение учебной задачи.

## events

Транспорт, промежуточные загрузки, удаления, решения родителя и готовые действия следуют существующему [каталогу обработчиков](event-queue.md); второй dispatcher не создаётся. Для пяти агентских событий закрытый execution artifact содержит `inputs.route`, входящий в fingerprint:

| Событие | Маршрут |
|---|---|
| upload.confirmed: purpose source-material или открытый запрос | sourceAnalysis без оценки ДЗ; разрешение запроса и новый план |
| upload.confirmed: обычная работа | все страницы → точное условие/критерии → homework-review → публикация/readback |
| help.requested | точный вопрос и попытка → один адресный следующий шаг → support revision |
| quiz.submitted | аудит ключа/альтернатив → открытые ответы → review → существующий граф продолжения |
| quiz.followup_requested | вся цепочка через history → открытые ответы → граф → validate/publish |
| material.ready | оригинал/SHA → издание/покрытие → семейная связь/ридер |

Фото запрошенной страницы больше не получает общую инструкцию оценить выполненную работу. Неизвестные типы остаются явной ошибкой маршрута, а не успешной пустой операцией. Устаревшие готовые пакеты обновляются адресно существующим exporter; новые поля плана меняют fingerprint и не разрешают исполнять старый ввод.

## Обновление разбора по новой педагогической политике {#guidance-refresh}

Прямая просьба о перегенерации создаёт отдельное операторское действие даже при неизменном МЭШ, SHA-256 источника и пустой очереди. Ревизия `parent-readable-hints-2026-10-25` применяется по [двум веткам графа](../reviews/card-generation-policy.md#explanation-and-hint): понятное взрослому объяснение средствами класса и подсказка от текущей точки ребёнка. Нельзя считать это выполненным по свежему сбору источников или по тому, что у гайда уже заполнены все поля.

Оператор после штатного полного `begin` составляет закрытый манифест всех актуальных разборов в запрошенной области: ребёнок/дата/taskId/номер, текущие guide/support revision, подтверждённая попытка и история помощи, основание обновления. Повторные назначения и выходные включаются отдельными адресатами; общий исходник допускает повторное использование проверенного полного решения, но не чужого состояния ученика. Область определяется прямым запросом и сохраняется в закрытом журнале; неподтверждённый источник остаётся адресной блокировкой, не поводом выдумать разбор. Исторические сданные результаты и уведомления не переписываются.

Для каждого пункта оператор заново проходит две смысловые проверки; перед публикацией изменённого текста повышает соответствующие существующие revision. Через штатные build/validate/problem-support/publish операции сохраняет ID, владельца, исходник, фото, попытки, зачтённые части, опциональность и уже отправленную помощь. Старый hint/reveal остаётся фактом прошлого; исправленный текст не отправляется ребёнку автоматически. Проверка после записи включает текущий закрытый guide и обе ролевые страницы: новый разбор доступен взрослому, полный путь/ключ отсутствует у ученика. В манифесте отдельно отмечаются проверено без изменения / перегенерировано / опубликовано и перечитано / заблокировано с причиной; каждое основание привязано к ревизии политики. Запрос завершён только после сверки полного манифеста, а не первой исправленной задачи. Недоступный источник не блокирует независимые пункты.

Это исполняемый агентом регламент. Автоматической очереди устаревания по педагогической версии, автоматической оценки понятности или перегенерации всех исторических гайдов в коде пока нет; существующие `routePlan` и CLI дают маршруты и запись/проверку данных. Обновлённый граф не следует объявлять уже выпущенными разборами без адресного readback.

Программирование в информатике и труде использует [предметный маршрут](../assessments/assessment-decision-graph.md#informatics): классификация темы и языка → подтверждённый intent → тест с листингами, исполненной проверкой ключа и чтением в обеих ролях. Внешний результат и семейная диагностика учитываются раздельно.

## limits

Адресный CLI `npm run guidance:refresh -- snapshot|apply PRIVATE_PLAN.json` сохраняет
исходники и живые role/evidence снимки до записи. Авторский JSON перечисляет даты,
taskId, точные stageID и новые тексты; чистый модуль `day/guidance-refresh.mjs`
запрещает смену источника/ID и пропуск адресата. Публикация идёт существующим
`day validate/problem-support`; после неё сравниваются все закрытые guide,
публичные support и неизменность фото/результатов/помощи/семейных решений.
Снимок и частичные квитанции приватны, source/CAS mismatch останавливает проход.
Исходный и новый page fingerprint допустимы только как исходное состояние либо
идемпотентный результат того же пакета; readback требует новый fingerprint.
При новом фото/помощи/семейном решении оператор читает закрытый delta и явно
подтверждает его SHA с основанием; без этого дальнейшая запись останавливается.
Это механический барьер, не оценка математической верности и понятности.

`prepare` валидирует все новые локальные тексты без публикации. В apply текущая
policyRevision и отдельные подтверждённые adultReadability/targetedHint с точным
набором taskId обязательны; несовпадение не допускает записи. В квитанцию входит
человеческое подтверждение, а не машинное заключение о качестве педагогики.

Реализованы механический выбор следующего шага, обнаружение пропущенного запроса и локальное извлечение плана. Автоматического интернет-поиска, определения книги по снимку, предметного решения и оценки фотографий нет. План не доказывает, что агент выполнил каждый шаг; конкретные результаты подтверждаются штатными owner/revision/readback gates. Publication audit не закрывает источник, а queued/processing/blocked не равны результату ученика. Новые правила не требуют выпуска PWA; серверный producer готовых поручений использует обновлённое ядро только после штатной установки runtime.

Для ссылки на прошлый урок действует [отдельный общий граф](../assessments/lesson-repetition.md):
сначала проверенная история своего ребёнка/предмета, затем все части и материалы,
и только отсутствующий остаток запрашивается у ученика. Старый зачёт письменного
сохраняется; новое повторение получает текущую ordinary-проверку. referenceDate,
source receipt и прежний высокий балл не отменяют её. Source-upload продолжается
до нового плана, публикации проверки и обеих ролевых проекций.
