# Простые LDD-логи и копирование через 🐞

## Основание

Пользователь19.10 прислал production-трассу: local student → grant/device matches=true с server snapshot → member-server student → card student/hasGuide=false. Это согласованный ученический вход, не доказательство использования старой роли вопреки server parent. Ветка предыдущего recovery в этом запуске не срабатывала и не объясняет его. Нельзя повышать роль в ответ на такой лог.

По прямой просьбе получена консультация «SDD v2 // impl», затем пользователь уточнил простое правило TypeScript-директив: `[Класс#метод]` или `[имяФункции]`, `[предыдущее → новое состояние]`, пояснение решения и безопасные структурированные детали. Новые scope API, декораторы и дерево вызовов не нужны. Начатый черновой адаптер удалён до коммита.

## Было → стало

`src/lib/browserAccessTrace.ts` сохраняет прежний ограниченный журнал и формирует читаемую строку с местом исполнения/переходом. `src/lib/personalAccess.ts`, `src/components/PersonalEntry.tsx`, `src/components/LearningRoute.tsx` и `src/lib/roleDiagnostics.ts` явно называют реальные функции и состояния на восстановлении, входе, чтении членства, выборе роли, показе и ошибках. Добавляется hash grant рядом с hashes person/device, без credential. Правила авторизации не меняются.

`src/components/DiagnosticsCopyButton.tsx` встроен в общую шапку `src/App.tsx`: круглая кнопка44px с 🐞 рядом с колокольчиком, включая мобильный/PWA и UI Kit. Один клик копирует локальный JSON; успех/ошибка через title и sr-only status, без нового экрана. ClipboardItem write начинается в обработчике клика до асинхронного ожидания для сохранения жеста Safari; без этой API используется writeText.

`src/App.css` размещает две44pxкнопки в прежнем слоте справа; мобильный gap8px и перенос строки сохраняют все прежние действия при недостаточной ширине. Бренд, установка, возврат и колокольчик не удаляются.

## Действия и роли

Экспорт ждёт hashes, очищает данные, включает текущие DOM-флаги и признак усечения/число потерянных записей. Лимит200событий/24часа прежний; старый журнал с неизвестной историей обрезки не объявляется полным. Нет токенов, имён, URL с секретами, raw exceptions, ответов/фото или полного localStorage. Нет новых Firestore reads, listeners, Rules или remote diagnostics. Кнопка ничего не отправляет в сеть.

Интерпретатор больше не затирает подтверждённое серверное членство более поздним local cache-hit. Смена identity сбрасывает прежнее основание. Это исправление анализа evidence, не назначения роли.

`scripts/browser-access-trace.mjs` выводит полноту/усечение в штатной безопасной сводке, не копируя весь журнал в вывод.

## Проверки

RED отсутствующей кнопки → один клик/успех/ошибка. Clipboard tests: отложенные hashes без canary-секретов и синхронный старт Safari/PWA write. Формат: функция/переход/описание и отбрасывание произвольных строк. Усечение сохраняется между запусками. Реальная интеграция до карточки воспроизводит присланный student-путь как characterization, а не объявляет его RED. Она выявила RED интерпретатора: последующий локальный hit стирал источник серверного доказательства; приоритет server membership исправлен.

## Согласование

Прямой запрос: консультация с TS-примерами, 🐞 для копирования одним кликом и разбор веб-входа. Последующее уточнение запрещает усложнение LDD. Существующая активная личная ссылка родителя проверяется и выдаётся по отдельной прямой просьбе о повторном входе; новые ссылки и полномочия не создаются.
