# Объяснение выполнения программы после теста

## Основание

Прямой запрос родителя01.11: разбор ошибки по информатике должен объяснять,
как работает программа и почему ответ отличается. Поле с многоточием и просьба
самостоятельно догадаться были отклонены. Документация Python подтверждает
правила первой истинной ветви, пустого диапазона, предварительной проверки while,
continue и break: https://docs.python.org/3/tutorial/controlflow.html .

## Было → стало

`assessment/question-guidance.mjs` требовал activity для любого предмета.
Теперь для вопроса с видимым кодом поддержан program-explanation: правило,
проверенная компактная таблица выполнения, причина расхождения и раскрытие
по чтению конструкции. Вопрос и activity запрещены. `src/lib/quiz.ts` типизирует
этот режим. `src/components/QuizResultCard.tsx` показывает объяснение после ошибки
без нового ввода, а правильным ответам не назначает action.
`src/components/ReviewBriefShowcase.tsx` показывает условный пример в UI Kit.
`scripts/quiz.mjs` принимает явный профиль ребёнка при адресном исправлении
метаданных, как create: несколько профилей не вынуждают менять реестр семьи.

## Действия и роли

Ответы, ключи и баллы сохраняются. Объясняется отправленная программа, новое
продолжение не раскрывается до отправки. Родитель и ребёнок получают один
проверенный разбор выполненного вопроса; доступ определяется прежним членством.
Исходные семейные материалы не включаются в Git. Режим не запускает код в браузере.

## Проверки

Регрессии CLI требуют код, таблицу, источник и отсутствие пустого ввода;
проверяется сохранение оценочного ключа. Renderer проверяется на точном объяснении,
таблице и отсутствии input. Полный check, live мобильный readback, неизменность
результата и ролевых связей завершают выпуск.

## Согласование

Прямой запрос родителя в текущем чате01.11 является основанием этой узкой замены
формата разбора программирования. Он уточняет общий протокол вопроса/действия;
для новых неотправленных тестов прежняя граница ответа сохраняется.
