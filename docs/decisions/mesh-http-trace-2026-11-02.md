# Прямой вход МЭШ и подробная локальная HTTP-трасса

## Основание

Родитель02.11 потребовал команду входа без инвайта и детальную диагностику запросов:
адреса, методы, заголовки, тела, HTTP-ответы, время и request IDs. Секреты должны
быть представлены начальными двумя символами, звёздочками и длиной.

## Было → стало

`npm run mesh:login -- --trace` вызывает прямой diary login, без Firebase,
приглашений и handoff. `--data-dir PATH` явно выбирает локальное хранилище,
по умолчанию используется обычный diary config текущего каталога.
При старом семейном workspace оператор передаёт именно его путь, чтобы
синхронизация использовала обновлённый доступ. Команда печатает выбранный каталог.

Каждый фактический вызов fetch получает локальный trace UUID и последовательный
номер; запрос и ответ имеют один ID, response содержит длительность. Header
серверного request/correlation ID сохраняется, если сервер его вернул; локальный
ID не выдаётся за серверный. Трасса оборачивает HTTP-транспорт каждого retry,
не меняет URL, заголовки, body, сигналы и режим redirect.

Печатаются URL/path/query, явные заголовки приложения, структура JSON/form-body,
статус, заголовки ответа, размер и SHA256 тела. Автоматически добавленные Node
заголовки не выдаются за наблюдённые. Неструктурное тело маскируется, JSON имеет
ограничения глубины/размера; response свыше64KiB не разбирается. Читается clone,
исходный поток остаётся доступен SDK. Стандартное OAuth error_description для
access_denied показывается полностью; неизвестные строки маскируются.

Секреты/идентификаторы и неизвестные header/поля выводятся как
`ab******** (длина: 426)`, восемь звёздочек обозначают скрытый остаток независимо
от размера; короткое значение до4символов скрывается целиком. Authorization
сохраняет название схемы. SMS, cookies, OAuth codes, login, password, client
credentials и токены следуют одному правилу. Файлы HTTP-логов не создаются.
`--show-password-prefix` дополнительно включает прежнюю проверку первых до4символов
пароля только в терминале; без флага ввод скрыт.

В прямом login username/password запрашиваются лениво перед первым password POST:
регистрационный отказ не заставляет повторно вводить пароль. Успешная регистрация
не повторяется ради запроса credentials. Роль и связь ребёнка проверяются в памяти;
secret.json заменяется только после успешной проверки. Неудача сохраняет старый доступ. При существующем подключении подтверждённый
actorPersonId обязан совпасть; вход другого взрослого не перезаписывает источник.

## Действия и роли

Эта диагностика не исправляет внешний access_denied и не подтверждает успешный вход
или42-дневный сбор. Реальную регистрацию запускает пользователь штатной командой;
сетевые тесты используют фикстуры и не создают OAuth-клиентов. Временные Request ID
существуют только в терминальном выводе, не передаются сервису дополнительным header. При ошибке печатаются локальные
кадры стека с файлами/строками без исходного сообщения и URL query.
Прежний connect:diagnose с invite остаётся для подключения другой семьи/компьютера.
Стандартная краткая диагностика runtime не получает локальные трассы.

## Проверки

Сверяются: тела/headers/query без полных секретов, серверный ID, локальная корреляция,
сохранение исходного запроса и Response, ошибки сети, ограничение больших ответов,
отказ регистрации до ввода пароля и отсутствие записи при неуспешной проверке роли.
Полный check обязателен. Работа нового входа подтверждается отдельно реальным входом,
проверкой владельца и полным сбором; наличие trace-команды этого не доказывает.

## Согласование

Прямой запрос родителя02.11: отдельный локальный логин МЭШ без invite, максимальная
HTTP-диагностика с заголовками и ID запросов. Последующее уточнение: токены не убирать,
а показывать первые пару символов, звёздочки и длину. Передача пароля/токенов в чат
и дополнительная выдача доступа не требуются.
