# Поэтапная сверка математического решения для родителя

## Основание

19.10.2026 родитель попросил проверить по коммитам и спецификациям, показывается ли в родительском математическом разборе, на каком именно этапе решения ученик ошибся, и внедрить это, если такого поведения нет.

## Было → стало

Было: спецификация уже задавала устойчивые ID этапов и сопоставление `review.items[].stageId`, а `ParentTaskGuide` умел показывать совпавший пункт внутри этапа. Однако публикационный валидатор требовал полного покрытия этапов только для `learning-route`; математический разбор мог быть опубликован без результатов по некоторым этапам. Интерфейс молча оставлял такие этапы без статуса.

Стало: публикация математического маршрута требует пункт проверки для каждого этапа. Родительский экран показывает число сопоставленных этапов, явно помечает старые/неполные этапы без результата и оставляет отдельную сводку правильности ответа и полноты хода. Незаполненный этап не считается ошибкой ученика.

## Действия и роли

Родитель видит статус и наблюдение ученика у соответствующего шага подготовленного решения. Проверяющий обязан адресовать вывод конкретному этапу через его устойчивый ID. Ученическая проекция и приватность родительского ключа не меняются.

## Проверки

`npm run check:spec` проверяет граф спецификаций и UI-контракт. При первом запуске карта и граф прошли, UI-контракт выявил устаревшие fingerprints для затронутых UI-файлов; fingerprints обновлены. Автоматические тесты не запускались в рамках этой задачи.

## Согласование

Прямой запрос родителя от 19.10.2026: проверить историю и спецификации, определить наличие поэтапного сравнения и реализовать его, если оно отсутствует.
