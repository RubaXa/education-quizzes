# Все дети имеют доступ к загруженным семьёй книгам

## Основание

Прямое уточнение родителя22.10: любой добавленный ребёнок автоматически имеет доступ ко всем ранее загруженным им учебникам. Требовать повторную загрузку одной семье из-за добавления ребёнка ошибочно. Уточнение школьного издания не должно закрывать чтение уже имеющегося оригинала.

## Было → стало

`storage/family-book-inheritance.mjs` отделяет право чтения семейной загрузки от персонального подтверждения издания. `storage/family-book-projection.mjs` после готовности страниц распространяет проверенный манифест другим активным детям семьи. `scripts/family.mjs` наследует готовые книги при add-child и предоставляет повторяемую share-books для существующих детей. Идентификаторы, явный школьный выбор и исходные персональные evidence сохраняются; физические PDF/PNG не копируются. Неактивный профиль младенца не активируется.

`src/lib/familyLibrary.ts` различает available и confirmed, считает каждую книгу один раз, сохраняет настоящие отсутствующие материалы. `src/components/FamilyLibrary.tsx` не превращает неизвестное расписание в красное требование учебников; книга не подписывается как принадлежащая только одному ребёнку. До готовности исходного манифеста распространение остаётся pending.

## Действия и роли

Правила Firestore не расширяются: новый ребёнок читает собственную адресную проекцию семейной книги. Публикует только доверенный процесс. Другие семьи, приватные ответы, работы, оценки и личные заметки не затрагиваются. Родительские операции загрузки и выбора материала сохраняются. Наследование права чтения не назначает школьное ДЗ младенцу и не подтверждает издание для нового урока.

## Проверки

`storage/family-book-inheritance.test.mjs`: новый ребёнок получает старую книгу и готовый манифест без загрузки; новая книга доступна существующему ребёнку; inactive/чужая семья исключены; персональные evidence не копируются; явный выбор не перезаписывается; повтор не создаёт записи; неправильный/неполный манифест не публикуется. `storage/family-book-projection.test.mjs` сохраняет проверку ревизий и полноты. `src/lib/familyLibrary.access.test.ts`: доступность отличается от подтверждения, настоящая недостача сохраняется, список не удваивается. `src/components/ParentHome.readBudget.test.tsx`: неизвестное расписание второго ребёнка не требует повторной загрузки и сохраняет семейную книгу; стартовые чтения не увеличены.

Полный `npm run check` прошёл:241 набор/1515 тестов, спецификации, реестр чтений, lint и сборка. Регрессия ложного требования при неизвестном расписании воспроизведена на исходном компоненте (RED) и проходит на исправленном (GREEN). Установочная dependency closure включает новый модуль наследования.

## Согласование

direct-request: текущее прямое уточнение родителя о наследовании всех загруженных им учебников любым добавленным ребёнком. Исправляется отвергнутое поведение существующего виджета; новый визуальный раздел не создаётся. Подготовленный код не объявляется выпущенным. До общего publish/install требуется координация параллельной работы по действующему протоколу; этот запрос сам по себе не используется как разрешение писать другим чатам.
