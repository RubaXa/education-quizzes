# Компактный разбор: исследование и общий кандидат UI Kit

## Основание

Прямой запрос родителя31.10: первая серия не выглядит существенно компактнее; нужны
новая визуальная проработка, поиск примеров интернет-образования, спецификации и
переиспользуемый UI Kit. Запрос разрешает этот локальный кандидат и документацию,
не утверждает автоматически редизайн действующих школьных карточек.

## Было → стало

Было: отдельный высокий макет чата, крупные отступы и повторная карточная композиция.
Стало: `src/components/ReviewBrief.tsx` и `src/components/ReviewBrief.css` задают один
компактный рабочий лист и три предметных представления. `src/lib/reviewBriefExamples.ts`
хранит синтетические образцы. `src/components/ReviewBriefShowcase.tsx` управляет локальными
примерами и состояниями. `src/UiKit.tsx` добавляет отдельный раздел, сохраняя существующие.
`src/education-design-tokens.css` добавляет изолированные токены нового компонента;
существующие имена/значения не меняются. `scripts/check-review-brief-viewport.mjs` рендерит
тот же React и настоящий CSS для проверки, вместо независимой HTML-копии.

Действующий `WorkReview`, его действия, фото, статусы, автоматическая проверка и
родительское принятие не изменены. Предыдущие решения UI Kit остаются основанием
остальных разделов. Кандидат ещё не выпущен на сайт.

## Действия и роли

Уточнение того же дня: родитель попросил показать именно уже опубликованный разбор
из первоначального скриншота. `ReviewBrief` получил соседние `details[]` с дословной
цитатой и опциональным предметным представлением; прежний `detail` совместим.
`ReviewVisual` дополнен `comparison`, а в синтетическом UI Kit показана проверка уже
найденного значения. Личный разбор не помещается в общие fixtures. Закрытый путь не
передаётся интерфейсу. Вопрос в реальном старом разборе уже имеет ответ в пояснении:
это обнаруженный дефект подачи, не ошибка ученика.

В UI Kit посетитель локально выбирает математику, русский или историю и состояние разбора.
Разрешённое пояснение раскрывается на месте. Семейные данные, вход, ответы и права не
имитируются переключателем роли. Компонент принимает уже авторизованное содержание,
не получает полный закрытый путь и не создаёт заданий или результатов.

## Проверки

`src/components/ReviewBrief.test.tsx` проверяет один вопрос, сохранение исходной строки,
сброс старого раскрытия, готовое и неясное состояния, отсутствие вычисляемой хронологии.
`src/UiKit.test.tsx` проверяет тот же компонент на трёх видах и сохранение группированной
навигации; число пунктов меняется15→16 из-за явно запрошенного раздела.
Геометрия, контрастные пары, длинная запись и раскрытия проверяются настоящим браузером
через `scripts/check-review-brief-viewport.mjs`. Команды: `npm run check:spec`,
`npx vitest run src/components/ReviewBrief.test.tsx src/UiKit.test.tsx`, `npm run typecheck`.
Статус прохождения команд фиксируется по фактическому запуску, не по наличию списка.

## Согласование

`direct-request`: родитель прямо потребовал повторную компактную визуальную проработку,
интернет-исследование, спецификации и UI Kit с переиспользуемыми компонентами.
Разрешение ограничено локальным проектом/каталогом; новый макет ещё не утверждён
для применения к школьным разборам. Действующий сервис и старые данные не мигрированы.
