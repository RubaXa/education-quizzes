# Даты рядом с выбранной попыткой

## Основание

Родитель16.10.2026 прислал скриншот UI Kit: нажатие часов первой строки открывает даты под последним тестом, связь с выбранной попыткой теряется. Прямая просьба исправить дефект относится к общему QuizCard, который используют день, список тестов и UI Kit. [Время попытки](../modules/assessments/quizzes.md#attempt-time), [цепочка](../modules/assessments/quiz-chain-proposal.md).

## Было → стало

В `src/components/QuizCard.tsx` отдельный map выводил даты после table. Теперь каждый тест имеет исходную строку и условную соседнюю строку дат с colSpan4. `Fragment` сохраняет устойчивый ключ и не добавляет лишний DOM. В `src/components/QuizCard.css` добавлен только отступ строки дат без верхней границы. Набор полей, формат времени, значок, токены, сортировка, цвета и состав карточки сохранены.

## Действия и роли

Обе роли открывают даты непосредственно под нажатой строкой. Другие часы закрывают прежний блок; повторное нажатие закрывает текущий. Текущая попытка сохраняет блок под шапкой, разбор ответов сохраняет отдельную область. Записей, новых чтений и подписок Firestore нет. История по умолчанию закрыта; универсальная родительская кнопка после100% сохраняется.

## Проверки

`src/components/QuizCard.time.test.tsx`: RED — две ошибки расположения в обеих ролях до исправления. GREEN — соседство DOM-строк, общий table и colSpan4, aria-controls/expanded, четыре даты, переключение, закрытие, неизменная сортировка. `src/components/QuizCard.history.test.tsx`, `src/UiKit.test.tsx`, полный check и живая обратная проверка опубликованного общего компонента обязательны.

## Согласование

`direct-request`: родитель16.10.2026 явно указывает, что компонент работает неправильно, потому что нажатый блок появляется под последним тестом. Это исправление отвергнутого поведения, отдельный макет не требуется.
