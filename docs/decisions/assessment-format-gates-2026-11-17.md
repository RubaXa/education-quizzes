# Проверяемый состав вместо обещанного баланса

## Основание

Родитель17.11.2026 обнаружил отсутствие выбора во всех вопросах математического
и исторического тестов и потребовал детерминированный CLI перед публикацией.
Старая математическая норма открытого ответа противоречит этому запросу;
новый владелец правила — [план форматов](../modules/assessments/format-plan.md).

## Было → стало

Было: short+long считались разнообразием; обычный тест не имел барьера баланса.
Стало: неизменяемые слоты selection/production/explanation из статистики,
проверка каждого ID/типа/варианта/ключа в validate/create/revise-open.
Файлы: `assessment/format-plan.mjs`, `scripts/quiz-format-plan.mjs`,
`assessment/decision-graph.mjs`, `scripts/quiz.mjs`, `package.json`.
Наблюдаемая при текущем разборе полная правильная фраза вместо одного термина
получает адресную смысловую коррекцию существующим механизмом ключа:
`assessment/canonical-short-key.mjs`; это не fuzzy grader и не изменение ответа.

## Действия и роли

Оператор получает закрытый план без Firebase. Живое продолжение сверяется с уже
читаемой полной историей. Ребёнок и родитель используют прежние QuizQuestionCard,
прежние действия и сохранённые попытки. Правка только заголовка/темы проверяет
тождественность вопросника прежним контрактом и не требует перегенерации теста.
Нового макета, расписания, доступа и пути чтения нет.

## Проверки

Регрессии фактических all-input составов; валидный смешанный тест; поддержка при
результате ниже85%; неизвестная история; подмена истории/плана/ID/ключа; диктант;
офлайн запуск и0600; неизменённый ответ при смысловой коррекции. Общий npm check.
Семантическая правильность и понятность отдельно проверяются по оригиналам;
численный баланс сам по себе их не доказывает.

## Согласование

Прямое текущее поручение родителя на внедрение CLI и обязательного барьера.
Смысловая сверка текущего ответа разрешена активным полным EducationSync.
Изменения не дают права массово переписывать начатые тесты.
