# Новое событие после недоступности источника

## Основание

22.10 пользователь сообщил: новые события МЭШ приходят в Telegram, но данные сайта остаются за предыдущий день. Read-only диагностика подтвердила здоровый runtime и доставку событий, однако внешний запрос и action lane оставались `blocked/source_unavailable`. Недоступный фрагмент старого учебного материала удерживал и более новые поколения. Успешный fanout доказывал только маршрутизацию, не запуск и публикацию.

## Было → стало

Вместо вечной блокировки смешанного Mesh/action состояния известный source-wait допускает один полный повтор на более новом meaningful generation. Уже накопленные поколения также обнаруживаются штатным claim после перезапуска. Дедупликация event ID сохраняется, debounce объединяет изменения, без новых поколений дорогой повтор не запускается. Каждое исполнение по-прежнему делает полный source check согласно контракту EducationSync.

Общий запрос получает новый ID и фиксирует snapshot поколения и action range. Attempted watermark учитывает внешний запрос и прежнюю action lane: полный проход старой lane не считается новыми данными. Старый source blocker записывается отдельно, lane становится `superseded`, а не выполненной. Диапазон включает все ещё не подтверждённые действия до актуального upper bound. Уже выполненные jobs штатный exporter пропускает. События во время исполнения остаются для следующего запроса.

## Действия и роли

Изменение касается dispatcher/оператора, не прав семьи или состава источников. Новых подписок, allowlist семей, отдельной очереди, ручного сигнала или нового расписания нет. Permission/manual-review и неоднозначное состояние не разблокируются автоматически. Активные queued/running/uncertain запросы и аренды не вытесняются; старое подтверждение не завершает новый request. Повторный source blocker сохраняется до доказанного разрешения; ни генерация запроса, ни Telegram receipt не означают global complete.

## Проверки

Регрессия воспроизводит внешний Mesh block, заблокированную action lane и более новые Mesh/action поколения. Проверяются точный frozen union, единственный claim, debounce, повторная блокировка смешанного запроса с последующим новым событием, отсутствие повторов на прежнем watermark, события во время исполнения, сохранение незавершённых jobs и запрет stale claim. Permission/manual-review и неизвестный attempted watermark остаются остановлены. Read-only status не публикует payload, токены и закрытые ссылки.

Полный `npm run check` и Git hooks выполняются перед выпуском. Для живого доказательства worker должен сам забрать накопленные реальные события, отправить запрос в существующий EducationSync, получить claim и результат публикации. Ручной resume/collect или искусственное событие такое доказательство не заменяют. Код и тесты не объявляются установленным runtime до отдельного install/readiness/readback.

## Согласование

Текущая просьба пользователя 22.10 — устранить отсутствие автоматической синхронизации после действий и обновлений МЭШ. Реализация через Luna Worker, основной агент проверяет код, тесты и выпуск в main, затем установленный worker и естественный запуск. Учебную проверку и публикацию выполняет штатный EducationSync по автоматически полученному запросу.
