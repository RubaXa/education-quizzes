# Семейное хранение и синхронизация олимпийской подготовки

## Основание

Пользователь поручил подключить семейные экраны, хранение, синхронизацию и проверенные учебные материалы, использовать общий дизайн и LDD, фиксировать допущения и проверять без дополнительных согласований.

## Было → стало

Вместо чистой модели с абстрактными портами добавлены Firestore-адаптер, обработчик с проверкой Firebase ID token и локальный сервер для эмуляторов. Проверенный каталог и подтверждённый класс дают основание для создания семейного назначения; сервер проверяет право, допустимость материала и ревизию в транзакции. Список, возобновление попытки и родительская детализация имеют отдельные разрешённые проекции. Запрос помощи хранит версии и привязку к фото; оператор замораживает входы разбора. Inbox и очередь распознают такие запросы и их ревизии.

Подготовлен production HTTP runtime с Firebase Admin и существующим `YandexDiskStorage`: он требует явный идентификатор проекта, точный список доверенных HTTPS origins и секрет Диска, отказывает при включённых эмуляторах. Двоичные запросы используют общую ограниченную HTTP-границу; фотографии остаются приватными. Транспортные события содержат только категорию маршрута, метод, код и длительность, без содержимого запросов, семьи, фото и токенов; отдельная связь с браузерной LDD-трассой пока не реализована. Runtime требует HTTPS ingress и выдачу сервисной учётной записи с доступом к Firestore и Firebase Auth; конфигурация, публичное размещение, работа секретов и readback в реальном окружении ещё не подтверждены.

Определения с ключами, документы попыток и семейные назначения закрыты прямому доступу клиента. Реального опубликованного API и серверного readback нет. Локальный HTTP runtime ограничен demo-проектом и двумя эмуляторами. Авторский учебный банк до завершения online-quiz процесса остаётся недоступным.

## Действия и роли

Родитель видит подходящий и неопределённый по классу каталог и может включить подготовку только при подтверждённом подходящем классе. Ученик видит выбранные подходящие записи. Операции урока и помощи проверяют право на ребёнка, действительность каталога, участие и разрешённый тренировочный материал; роль не принимается из тела запроса. Серверный разбор ученика не содержит закрытого ключа; родитель получает детализацию при проверенной роли. Двоичные маршруты загрузки и выдачи подключены в локальном emulator runtime через внедрённый storage-порт, а production runtime связывает их с существующим приватным Яндекс.Диском; действующий сервер и проверка настоящих фотографий ещё не подтверждены.

Оператор запускает `olympiad.help-start` через единое ядро Education с явным `--apply` и устойчивым `operationId`: операция замораживает ревизию, адресно перечитывает источник и скачивает проверенные приватные фото в закрытую `.local/olympiad-help/`. Фактический предметный разбор выполняет наставник. `olympiad.help-finish` принимает файл с подготовленным ответом, атомарно записывает ответ и подтверждает точный readback. Повтор с тем же `operationId` и ответом безопасен; иной ответ с тем же ID отклоняется. Новые добавления во время обработки остаются в очереди. Данные и пути фото доступны только в закрытой квитанции оператора.

## Проверки

Локальные интеграционные тесты проверяют адаптер, ролевые проекции, отзыв, чужого ребёнка, изменения участия и границу HTTP; отдельные тесты — очередь и версии запросов. Интеграционные тесты Auth и Firestore Emulator ранее прошли с локально установленной Java; это не проверка живого окружения. Тесты production HTTP проверяют список origins, отказ от эмуляторов и отсутствие чувствительных данных в логах. Операторские тесты проверяют приватность фото, контрольную сумму, ревизии, повтор и конфликт ответа. Статический тест правил не заменяет проверку эмулятором или действующим окружением. Настоящие семейные данные и материалы не записывались.

## Согласование

Прямое поручение пользователя 27–28.10.2026 реализовывать и проверять согласованный сценарий автономно, не выдавая локальную подготовку за выпуск.

## Состояние развёртывания 28.10

Production runtime подготовлен, но не выпущен. В проекте Firebase проверен активный биллинг, Firestore расположен в `europe-west1`; Cloud Run, Cloud Build, Artifact Registry и Secret Manager на момент проверки отключены. Отдельный минимальный серверный пакет проверен установкой зависимостей, импортом и аудитом; контейнер не собран, локальный Docker не отвечает. До выпуска нужно собрать и проверить образ из актуального main, настроить отдельную identity с ограниченным доступом к Firestore и проверке Firebase, ограничить доступ к приватному секрету Диска, настроить доверенные origin и лимит масштабирования, затем выполнить живую проверку доступа, фото, очереди и адресный readback. Min instances=0 не исключает оплату запросов, сборок и хранения; max instances ограничивает параллелизм, а не общий счёт. Услуги пока не включались, публичный сервер не создан. Подробнее о тарифной модели и бюджете: [Cloud Run](https://docs.cloud.google.com/run/docs/configuring/billing-settings), [бюджеты Google Cloud](https://docs.cloud.google.com/billing/docs/how-to/budgets).
