# Барьер зачёта, история знаний и адресные сценарии UI Kit

## Основание {#reason}

Прямое требование16.11: полнота условий и критериев проверяется перед зачётом,
результат обновляет знания ребёнка, каждый узел/переход связан с контрактом и
решением, а UI Kit показывает реальные предметные карточки обеих ролей.
Регрессии: пропуск содержательного требования о национальном блюде, неполный
учительский лист и пустая шапка встроенного теста. Независимый аудит обнаружил
обходы записи без criteria trace, неполную проверку ручных баллов и потери истории.

## Было → стало {#change}

Опись хранится независимо от результата в закрытом вложенном документе: обычная
перепубликация родительского гида не стирает её. Зачёт требует совпадения полного
набора критериев, актуального источника и наблюдений. Авторский required:false не
отменяет прямое требование. Неизвестный критерий даёт cannot-assess, не ошибку ученика.
Проверка теста использует закрытые рубрики, проверяет границы/суммы баллов и свежесть
прежнего разбора; изменения хранятся в истории. Результат и адресные наблюдения знаний
записываются атомарно; микроответ имеет только scope micro-step. Освоение не выводится
автоматически, прежние знания о навыке сохраняются.

Один реестр связывает правила предметов и общих действий с узлами, рёбрами,
спецификациями, основанием и UI-сценариями. Страница дня и UI Kit используют одну
рамку карточки и рабочие компоненты. Составные сценарии выделены из примитивов.
Встроенный QuizCard сохраняет часы/действия без пустого цветного блока шапки.

## Действия и роли {#roles}

Рубрики теста, описи и learningEvidence закрыты от клиента. Ученическая проекция
получает прежний безопасный разбор, родительский полный путь остаётся отдельно.
В UI Kit только синтетические данные; переключение роли, состояния и предмета не
читает семейные документы и не пишет оценку. Метаданные графа не добавляют технические
блоки в ученическую карточку: инспектор принадлежит только UI Kit.

## Проверки {#verification}

Обязательные отрицательные случаи: пропущенный national criterion; неверный ответ
при верной грамматике; отключение критерия без источника; невыполненное дополнительное действие не ухудшает зачёт обязательного этапа; лист1,2,4,6,7 без последнего
номера и без version flag; устаревший источник/разбор; недопустимые ручные баллы;
различимые1/3и2/3; повтор записи; сохранение старого mastery; микроответ без общего
зачёта; отсутствие закрытых данных в public projection. Для UI — покрытие реальных
правил, графовые адреса обеих ролей, закрытое начальное состояние, раскрытия и320px.
Сквозная регрессия исполняет настоящий CLI export → criteria → отказ неполного зачёта → review и наблюдение → следующий адресный capture, с изолированным хранилищем без семейных записей. Пройти общий npm run check и штатные hooks. Выпуск данных и PWA подтверждаются отдельно.

## Согласование {#authorization}

Пользователь прямо поручил16.11 закрыть пробелы в рабочем процессе и связать все
карточки/переходы с графом через UI Kit, включая реальные родительский и ученический
виды. Ранее данное разрешение на проверенные внутренние задачи и штатный выпуск действует.
