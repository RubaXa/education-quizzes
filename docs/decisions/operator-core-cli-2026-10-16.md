# Штатное операторское ядро CLI

## Основание

Родитель 16.10.2026 уточнил, что нужны переиспользуемые CLI-инструменты на общем ядре, фиксированная модель данных, метрики, тесты и граф решения; разовые inline-скрипты не должны становиться регулярным способом синхронизации.

## Было → стало

Прежде агент вручную собирал цепочки из разрозненных команд и мог принять успешный выход процесса за подтверждённую публикацию. `scripts/education.mjs` теперь принимает только операции из `operator/operation-contract.mjs`, исполняет их через `operator/run-operation.mjs`, сохраняет закрытую квитанцию и показывает безопасные метрики. `scripts/sync-project.mjs` возвращает измерения стадии `plan`. `scripts/submissions.mjs` получил read-only `validate` и адресное обратное чтение после записи; `storage/review-readback.mjs` проверяет сохранённые документы. Произвольная строка «доказательства» не переводит глобальную фазу в `complete` через новое ядро.

## Действия и роли

Оператор вызывает фиксированный CLI и анализирует отчёт. Агент создаёт содержательный пакет только после проверки источников и предметного решения. Родительский и ученический экран не меняются; существующие маршруты данных остаются. Новое обратное чтение возникает лишь после публикации конкретного разбора.

## Проверки

`operator/operation-contract.test.mjs` проверяет реестр и отпечатки; `operator/run-operation.test.mjs` — квитанции, повторы и отказ от неподтверждённой записи; `storage/review-readback.test.mjs` — адресную сверку; `scripts/check-ui-contract.test.mjs` — включение ядра в барьер решений. Полный `npm run check` включает реестр Firestore-чтений и сборку.

## Согласование

Прямой запрос родителя в текущем разговоре: «не скилы», а «нормальные CLI-tools», «ядро», «всё покрыты тестами», «метрики», стабильная модель получения, анализа и сохранения. Видимые элементы интерфейса этим решением не меняются.
