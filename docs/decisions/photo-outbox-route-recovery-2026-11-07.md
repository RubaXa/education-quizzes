# Восстановление фото независимо от страницы дня

## Основание

Родитель07.11попросил устранить зависание русского246и видеть точный этап,
а не каждый раз просить повторную загрузку. На сервере исходная заявка
awaiting-upload, файл отсутствует, права действуют. Старых клиентских этапов нет:
точную причину этой конкретной остановки задним числом определить нельзя.

## Было → стало

Воспроизводимый дефект: передача запускается подпиской открытого дня; переход
на главную до выдачи URL или повторное открытие приложения без дня не читает
сохранённую IndexedDB очередь. Отсутствующий Blob при автоматическом запуске
молча забывается. Оба сценария требуют явного восстановления/диагностики.

## Действия и роли

App запускает один локальный drainer, независимо от маршрута. Он просматривает
только ключи собственной IndexedDB очереди, до8адресных заявок за проход с
ротацией; никаких глобальных Firestore запросов/подписок. Видимый онлайн-клиент
просыпается при запуске, online, pageshow, focus и каждые30секунд. Чужой uid
не передаёт и не перепривязывает файл; повтор использует прежние ID и байты.
Оригинал удаляется только после pending/reviewed/deleted. Ошибка сети не удаляет
локальный файл. Сетевые чтения имеют ограниченное ожидание; активный PUT один.

Локальная диагностическая трасса фиксирует allowlisted этапы, без URL/секретов,
имени файла и текста работы. Серверное поле clientTransfer — только последняя
диагностическая проекция исходного устройства: phase,code,at,attempt,httpStatus.
Оно не меняет статус, права, исходные байты, оценку или business-event очередь.
Разрешённая запись ограничена прежним deviceUid и действующим студентом семьи;
нет клиентских произвольных строк или подписок. Ошибка телеметрии не блокирует PUT.
Данные клиента — диагностическое сообщение, не доказательство доставки. Доставка
подтверждается отдельно HEAD/хэш и серверным pending+stored.

Этапы: waiting-link, reading-local, missing-local, checking-source, sending,
put-complete, confirming, uploaded, failed. Без новой записи старой PWA CLI
явно показывает client-not-observed, а не выдумывает стадию. При missing-local
можно адресно попросить исходное фото; при сетевом сбое drainer повторяет передачу
сохранённого файла без нового задания ученику. Не выдавать проверенный код за
выпущенную PWA или завершённую реальную передачу246.
