# Общий архив семей и ссылки на отдельные файлы

## Согласовано с родителем 10.10.2026

1. Исходные артефакты всех семей лежат на **одном сервисном Яндекс.Диске**. Папки изолируются по непрозрачным `familyId`, `childId`, дате и `artifactId`; имена людей и названия заданий не являются частью пути. Firestore хранит связи, состояния и метаданные, а не байты файлов.
2. Доступ строится на случайных неперебираемых ссылках. Ссылка сама является правом доступа; отдельный вход для её получателя не нужен. Авторизация родителя через mos.ru нужна для получения данных МЭШ и не должна внезапно становиться требованием для просмотра пересланного файла.
3. **Пересылаемая ссылка даёт доступ ровно к одному файлу.** Личные ссылки ребёнка и родителя могут иметь иной объём прав, но ссылка на артефакт не раскрывает соседние файлы, задания или семью.
4. Идентификатор ссылки постоянен. Родитель видит список выданных ссылок и может закрыть конкретную ссылку без удаления исходника или истории. Закрытый токен не переиспользуется. Для проверки доступа на каждом открытии учитываются состояние ссылки и её область действия.
5. Журнал должен учитывать **все открытия**. Просмотр через личную ссылку ребёнка может быть отнесён к ребёнку; просмотр отдельно пересланной ссылки записывается как анонимный. Ни IP, ни устройство сами по себе не доказывают, что файл открыл ребёнок.
6. Только родитель создаёт и закрывает ссылки на отдельные файлы ребёнка. Ребёнок видит свои материалы через личный доступ, но не управляет пересылкой.
7. Подробные события просмотров хранятся **один учебный год**; после этого можно оставить только агрегаты без отдельных посещений. Точную границу учебного года и процедуру удаления событий следует задать перед реализацией.
8. При подключении других семей файлы и журнал доступны круглосуточно, даже когда личный Mac выключен. Локальный процесс остаётся переходным решением для одной семьи; постоянно доступный шлюз обязателен для масштабируемой версии.
9. Одинаковый учебник или иной общий исходный материал хранится **одним оригиналом**. Связи с семьями, права просмотра и события доступа остаются отдельными; общий файл сам по себе не открывает доступ к чужим данным.

## Следствие для устройства системы

Для полного журнала недостаточно отдавать браузеру постоянный публичный URL Яндекс.Диска: его можно открыть вне Education и обойти журнал. Нужен постоянно доступный медиа-шлюз Education. Он получает bearer-токен ссылки, читает её состояние и область в Firestore, пишет событие доступа, затем отдаёт файл с Яндекс.Диска. OAuth-токен Диска остаётся на доверенной стороне; браузер его не получает. Кэширование и диапазонные запросы должны сохранять возможность полного учёта открытий. Закрытие ссылки прекращает новые выдачи байтов, но не удаляет оригинал.

Модель данных: `StoredObject` (путь, хэш и свойства единственного оригинала), `Artifact` (связь оригинала с семьёй, ребёнком, источником или заданием), `ShareLink` (неперебираемый токен, ровно один `artifactId`, статус, кем/когда создан, кем/когда закрыт) и `AccessEvent` (токен/файл, время, вид ссылки, подтверждённый участник либо `anonymous`, результат выдачи). Разделение физического оригинала и семейной связи позволяет переиспользовать общие учебники, сохраняя отдельные права. События добавляются, а не переписываются. Сам токен хранится как секрет; для поиска и журналов предпочтителен его хэш.

## Текущее состояние и граница следующего этапа

Сейчас ученическое фото уже отправляется напрямую на Яндекс.Диск через доверенный локальный процесс; в Firestore остаются только заявка и метаданные. Файлы для просмотра пока публикуются Диском по bearer-URL. Такой адрес можно переслать, а прямой просмотр вне Education не попадает в полный журнал. Текущий Mac обслуживает загрузку одной семьи; для независимой работы многих семей нужен доступный постоянно доверенный выдающий и медиа-шлюз. Эта часть **не реализована** текущим выпуском.

Открыто для следующего интервью: точная дата окончания учебного года и судьба агрегатов; какие материалы учителя можно пересылать; лимиты и эксплуатация единого Диска; конкретное размещение постоянно доступного сервиса.
